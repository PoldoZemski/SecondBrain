## Что такое скилл и зачем он нужен

Скилл - файл `SKILL.md` в папке `00-atlas/agents/skills/<имя>/`. Агент читает его при выполнении задания. Скилл описывает формат карточки, процедуру работы или набор правил - то, что должно применяться единообразно.

Скиллы решают проблему дублирования. Без них одно и то же правило (например, формат тегов) приходится прописывать в карточке каждого агента, и при обновлении правила нужно править все карточки. Со скиллами правило живет в одном месте, а агенты на него ссылаются.

Подробно о природе скиллов как контракта: [урок - скиллы агентов](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D1%8B%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2.md).

## Скиллы системы

В папке `00-atlas/agents/skills/` лежат 25 скиллов. Назначение взято из шапок SKILL.md.

**Общие правила работы агентов**

| Скилл | Что делает | Когда применять |
|---|---|---|
| agent-run | Общий порядок запуска агента: очередь заданий (по одному, у каждого свой отчет), предложения, три вида отчетов, реестр, запреты | Первое действие при каждом запуске агента |
| yaml-frontmatter | Единые правила YAML-блока для всех типов карточек | Для любой карточки |
| entity-relations | Типизированные связи между карточками через таблицу ребер в теле карточки, словарь глаголов | Вместе с любой карточкой, у которой есть раздел «Связи» |
| naming-check | Проверка имен файлов и папок на соответствие правилам CLAUDE.md | Перед созданием любого файла и при переименовании |
| str | Упрощенный технический русский - стандарт письма | К любой русской прозе |
| task-card | Карточка задания для агента в `06-inbox/tasks/` | При постановке задания |
| task-report | Отчет по заданию или исполненному предложению в `99-archive/tasks-done/reports/`, имя `<агент>-<ГГГГ-ММ-ДД>-<имя>-отчет.md` | При завершении задания или исполнении предложения |
| proposal-card | Формат предложения агента в `06-inbox/proposals/`: одна проблема - одно предложение, разделы для решения и комментария пользователя, предложение-замена после отклонения | Когда агенту нужно решение пользователя |
| skill-maintenance | Управление скиллами: версии, структура, создание, вывод из употребления, проверка целостности | Рабочий скилл методиста |

**Карточки**

| Скилл | Что делает | Когда применять |
|---|---|---|
| contact-card | Карточка контакта в `05-contacts/` | Не для компаний и организаций |
| org-card | Карточка организации в `04-resources/организации/` | Организация без договора, проекта или согласованного КП - не клиент |
| place-card | Карточка места в `04-resources/города и регионы/` | Город, район, регион, страна |
| concept-card | Карточка понятия или сферы деятельности в `04-resources/понятия/` | Определение, элементы, применение |
| idea-card | Карточка идеи в `10-ideas/<тема>/` | Идея, не ставшая проектом |
| process-card | Карточка процесса в `11-processes/` | Последовательность шагов от входа к выходу |
| client-card | Карточка клиента в `01-clients/` | Не для людей и не для отдельных проектов |
| project-card | Карточка проекта и содержимое папки проекта в `01-clients/<клиент>/` | Не для карточки самого клиента |

**Консалтинг и встречи**

| Скилл | Что делает | Когда применять |
|---|---|---|
| source-extract | Извлечение фактов из транскриптов встреч и документов в выжимку с привязкой к источнику | Перед сборкой отчета |
| diagnostic-report | Диагностическое заключение по консалтинговому проекту из выжимки фактов | После source-extract |
| meeting-osint-cards | По имени и дате встречи берет запись из tl;dv, ищет в хранилище и OSINT, создает карточки | По запросу пользователя |

**Контент**

Пять скиллов для публикаций автора (подписи к видео, посты для каналов и клубов, сценарий инвестиционной презентации, проектирование конвейера контента). Они персональные, в стартовый набор и в этот репозиторий не входят. Свои скиллы такого рода создайте по схеме из раздела «Как заказать новый скилл».

## Внешние скиллы

Часть скиллов поставляют плагины Claude Code на сервере. В `00-atlas/agents/skills/` их нет, хранилище их не версионирует.

| Скилл | Что делает | Применимость на сервере |
|---|---|---|
| obsidian-markdown | Формат wiki-ссылок, вставок, callout-блоков, свойств YAML | применим |
| obsidian-cli | Работа с приложением Obsidian из командной строки | неприменим: требует запущенного приложения Obsidian |

Упоминание внешнего скилла в карточке агента без файла в `skills/` - норма. Список внешних скиллов ведет методист в своей карточке и меняет только по заданию.

## Роль методиста

Методист - единственный агент с правом изменять содержимое `00-atlas/agents/skills/`. Остальные агенты скиллы читают, но не правят. Имя в полях `for` и `from` - русское: `методист`. Латинское имя `methodologist` используется только в именах скрипта, юнитов и лога.

Методист делает две вещи:

- Еженедельный обзор. Собирает раздел «Предложения по улучшению» из отчетов всех агентов, делит находки на технические (правка скиллов, его зона) и организационные (правила CLAUDE.md, структура, не его зона). Технические оформляет как предложения в `06-inbox/proposals/`.
- Выполнение заданий. Только по явному заданию с `for: методист` в `06-inbox/tasks/`. Без задания методист скиллы не правит, даже если проблема очевидна.

Скрипт запуска: `run-methodologist.sh`. Еженедельный обзор запускается по расписанию раз в неделю.

## Как заказать новый скилл

1. Поставьте задание методисту в `06-inbox/tasks/` по скиллу task-card:

```
---
type: task
for: методист
task_status: к исполнению
created: ГГГГ-ММ-ДД
source: мое решение
tags:
  - task
  - скиллы
---

Создай скилл <имя-скилла>.

Скилл должен описывать: <что именно>.

Агенты, которые будут его использовать: <список>.
```

2. Методист создаст скилл и напишет отчет в `99-archive/tasks-done/reports/`.
3. Добавьте ссылку на скилл в карточки агентов, которые будут его использовать (отдельное задание методисту или правка вручную).

Новый скилл получает `skill_status: черновик`, а агенты применяют только скиллы со статусом `действует`. Скилл, на который уже ссылаются CLAUDE.md или agent-run, создавайте сразу со статусом `действует`.

## Как заказать изменение существующего скилла

Поставьте задание методисту с конкретной формулировкой: что изменить и почему. Задание называет текущую версию каждого затронутого скилла.

Если изменение затрагивает правило из CLAUDE.md, сначала правится CLAUDE.md (это делает только пользователь). Задание методисту в это время стоит со статусом `task_status: ждет решения`: агент его пропускает. После правки CLAUDE.md смените статус на `к исполнению`.

Если изменение найдено агентом в ходе работы, агент выносит предложение в `06-inbox/proposals/` и скилл сам не правит. Методист видит предложение при еженедельном обзоре и оформляет задание.

## Где живет общее правило

Правило, которое касается нескольких скиллов, живет в одном месте. Скиллы ссылаются на него и не повторяют его текст.

- Правила оформления YAML - скилл yaml-frontmatter.
- Формат задач для секретаря и раздел «Следующие шаги» в карточках - CLAUDE.md, раздел «Задачи и todo». Подробно: [урок - задачи в карточках и секретарь](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%B7%D0%B0%D0%B4%D0%B0%D1%87%D0%B8%20%D0%B2%20%D0%BA%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B0%D1%85%20%D0%B8%20%D1%81%D0%B5%D0%BA%D1%80%D0%B5%D1%82%D0%B0%D1%80%D1%8C.md).
- Формат предложения агента - скилл proposal-card, правила решения по предложению - CLAUDE.md, раздел «Предложения агентов». Подробно: [урок - предложения агентов](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%80%D0%B5%D0%B4%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D1%8F%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2.md).
- Имена и места отчетов - CLAUDE.md, раздел «Отчеты агентов», формат отчета - скилл task-report, порядок для агента - раздел «Отчеты» скилла agent-run. Подробно: [урок - отчеты агентов](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BE%D1%82%D1%87%D0%B5%D1%82%D1%8B%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2.md).

## Версионирование скиллов

Каждый скилл несет версию в `metadata.version` по semver: patch для формулировок и шапки, minor для новых правил, major для структурной переделки. Каждое изменение - новая строка в разделе «История изменений»: дата, что изменилось, почему.

Задание, которое ссылается на скилл, называет его версию. Если скилл обновился между постановкой и выполнением задания, агент фиксирует расхождение в отчете.

## Вывод скилла из употребления

Устаревший скилл получает `skill_status: устарел` и переносится в `99-archive/skills-retired/<имя>/`. Удаление ссылок на него из карточек агентов - отдельное задание, не фоновая работа методиста.

## Чек-лист выхода (скилл готов к использованию)

- [ ] Файл `00-atlas/agents/skills/<имя>/SKILL.md` создан
- [ ] Шапка содержит `name`, `description`, `metadata` (author, created, version, origin, skill_status)
- [ ] Есть раздел «История изменений» с первой строкой
- [ ] Скилл добавлен в таблицу выше
- [ ] Агенты, использующие скилл, ссылаются на него в своих карточках
