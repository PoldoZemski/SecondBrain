## Выбор сервера

Нужен сервер с Ubuntu 22.04 LTS: 4 vCore, 6 GB RAM, 100 GB SSD и больше. Этого хватает для Traefik, n8n, Langflow с PostgreSQL, JupyterLab, CouchDB, моста и агентов Claude Code. При 6 GB памяти включите swap и не запускайте лишних сервисов.

Если сервер стоит в стране, где заблокирован доступ к API нейросетей (например, в РФ), заранее подготовьте канал через прокси: раздел про прокси в [05-claude code на сервере](05-claude%20code%20%D0%BD%D0%B0%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%B5.md). Это добавляет заметный кусок работы.

Как подключиться к серверу, описано в [00-с чего начать](00-%D1%81%20%D1%87%D0%B5%D0%B3%D0%BE%20%D0%BD%D0%B0%D1%87%D0%B0%D1%82%D1%8C.md).

## Первичная настройка (от root, один раз)

### 1. Обновление и базовые пакеты

```bash
apt update && apt upgrade -y
apt install -y ufw fail2ban git curl htop
```

### 2. Пользователь-администратор

В повседневной работе root не используется. Создайте администратора и дайте ему sudo:

```bash
adduser admin_name
usermod -aG sudo admin_name
```

Если провайдер выдал вход по ключу только для root, скопируйте ключ новому пользователю:

```bash
rsync --archive --chown=admin_name:admin_name ~/.ssh /home/admin_name
```

Откройте второй терминал и проверьте вход новым пользователем. Первый терминал не закрывайте. Признак успеха: в новом терминале команда `sudo whoami` выводит root.

Когда вход работает, закройте вход root по SSH:

```bash
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
systemctl restart ssh
```

Дальше вся работа идет от администратора, команды с sudo.

### 3. Swap (обязателен при 6 GB)

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 4. Файрвол: запрещено все, что не разрешено

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
ufw enable
```

Правило на всю жизнь сервера: каждый новый открытый порт - осознанное решение с записью в карточку инфраструктуры. Локальные сервисы (прокси, панели, админка CouchDB) слушают только 127.0.0.1.

Порты, которые публикует Docker, файрвол UFW не фильтрует. Как их закрыть, описано в [02-docker и traefik](02-docker%20%D0%B8%20traefik.md), раздел «Порты контейнеров и файрвол».

### 5. fail2ban

```bash
systemctl enable --now fail2ban
```

Стандартной защиты SSH достаточно для старта.

## Правила публикации сервисов

1. Включайте аутентификацию до первой публикации сервиса, не после.
2. Используйте встроенную аутентификацию сервиса. Basic Auth на прокси - запасной вариант: он конфликтует с приложениями типа SPA.
3. Сервису, которому не нужен домен (бот на long polling), не создавайте метки Traefik и не публикуйте порты.
4. Раз в месяц выполняйте `docker ps`, смотрите список открытых портов и спрашивайте себя: нужен ли каждый сервис. Ненужный сервис удаляйте.

Почему так: [урок - публичные сервисы без auth](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%83%D0%B1%D0%BB%D0%B8%D1%87%D0%BD%D1%8B%D0%B5%20%D1%81%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D1%8B%20%D0%B1%D0%B5%D0%B7%20auth.md).

## Мультипользовательская схема под агентов

Создайте ее сразу, даже если агенты появятся позже: переделывать права на живой системе дороже.

```bash
sudo groupadd -g 1600 secondbrain
sudo useradd -m -s /bin/bash -u 1500 brain
sudo usermod -aG secondbrain brain
sudo usermod -aG secondbrain admin_name
sudo mkdir -p /opt/second-brain/vault
sudo chown -R brain:secondbrain /opt/second-brain
sudo chmod -R 2775 /opt/second-brain/vault
```

Смысл схемы:

- Агенты работают от непривилегированного пользователя brain без sudo.
- Каталог хранилища /opt/second-brain/vault - общая зона. Бит setgid (2775) заставляет файлы любого пользователя наследовать группу secondbrain.
- Администратор в группе secondbrain читает логи и файлы агентов.
- Числа 1500 и 1600 фиксированы: они же прописываются в compose-файлах (`user: "1500:1600"`), поэтому контейнеры и процессы хоста видят одни и те же номера.
- Все операции с файлами хранилища на сервере выполняйте от brain (`sudo -u brain ...`), не от root: файл, созданный root, мост записать не сможет.

Типичные ошибки прав: [урок - права и владельцы в multi-user](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%80%D0%B0%D0%B2%D0%B0%20%D0%B8%20%D0%B2%D0%BB%D0%B0%D0%B4%D0%B5%D0%BB%D1%8C%D1%86%D1%8B%20%D0%B2%20multi-user.md).

## Секреты

- Секрет хранится в одном месте: файле .env с правами 600 рядом с compose-файлом (для процессов вне Docker: /home/пользователь/.env).
- В compose-файлах и скриптах используйте подстановки `${VAR}`, не литералы.
- В заметки и документацию секреты не записывайте. Карточка указывает, где лежит секрет, но не сам секрет.
- Если пароль где-то засветился, смените его сразу.
- Генерируйте секреты командой `openssl rand -hex 24`: такой алфавит не содержит символов, которые ломают bash, JSON и YAML.
