# 10. Как завести нового агента

Предыдущая: [09-запуск claude code вручную](09-%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%20claude%20code%20%D0%B2%D1%80%D1%83%D1%87%D0%BD%D1%83%D1%8E.md). Следующая: [11-obsidian mcp для claude desktop](11-obsidian%20mcp%20%D0%B4%D0%BB%D1%8F%20claude%20desktop.md).

Опирается на: [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md) (принципы и шаблоны конфигов, слои 1-5) и [05-claude code на сервере](05-claude%20code%20%D0%BD%D0%B0%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%B5.md) (установка Claude Code и политика инструментов: делаются один раз на всю систему, а не на агента).

Чек-лист собирает в один проход шаги для уже развернутой системы: VPS, CouchDB, мост и Claude Code готовы по главам 01-05, есть хотя бы один рабочий агент. Используйте его, когда нужно завести еще одного агента.

## Имена и пути

- пользователь агентов: brain
- рабочий каталог агентов (корень хранилища, где лежит CLAUDE.md): /opt/second-brain/vault
- скрипты запуска: /opt/second-brain/automation/scripts/run-<имя-латиницей>.sh
- логи: /opt/second-brain/automation/logs/<имя>.log
- systemd-юниты: <имя-латиницей>-watch.path и <имя-латиницей>.service (systemd не работает с кириллицей в именах юнитов, поэтому нужно латинское имя)
- ключ и прокси: /home/brain/.env

Латинское имя агента фиксируется при создании и не меняется: оно входит в имя скрипта, юнитов, лог-файла и технической карточки. Агенты стартового набора:

| Русское имя | Латинское имя | Скрипт запуска | Модель |
|---|---|---|---|
| архивариус | archivist | run-archivist.sh | haiku |
| библиотекарь | librarian | run-librarian.sh | haiku |
| секретарь | secretary | run-secretary.sh | haiku |
| методист | methodologist | run-methodologist.sh | haiku |
| бизнес-аналитик | business-analyst | run-business-analyst.sh | sonnet |
| нетворкер | networker | run-networker.sh | claude-sonnet-5-5 |

В полях `for` и `from` заданий и предложений всегда стоит русское имя агента: `for: методист`, а не `for: methodologist`. Агент находит свои задания по имени, указанному в разделе «Роль» его карточки. Задание с латинским именем агент не увидит.

## Карточка агента

Скрипт запуска передает текст карточки в `claude -p` целиком. Карточка - это промпт агента. Отсюда правила:

1. Карточка содержит только особенное для этого агента. Общий порядок запуска и общие правила всех агентов живут в скилле agent-run.
2. Поведение, которое нужно нескольким агентам одинаково, оформляется скиллом через задание методисту. Копия правила в нескольких карточках не допускается.
3. Стиль краткий: роль, пути, условия, команды. Без объяснений «почему», без сравнений с другими агентами, без описания инфраструктуры.
4. В тексте инструкций нет wiki-ссылок. Файл, который агент должен открыть, называется путем.
5. Связи с другими заметками стоят только в последнем разделе `## Связи`, таблицей по скиллу entity-relations: что агент читает, какой реестр ведет, на какие уроки опирается, где описан технически. Ссылок на карточки других агентов нет. Скилл agent-run запрещает агенту открывать заметки из этого раздела без прямого требования задания.
6. Правила отчетов и предложений в карточку не копируются. Они живут в скиллах agent-run, task-report и proposal-card. Если агент пишет отчет особой формы, карточка называет только добавленные разделы.

Шаблон карточки:

````markdown
---
type: агент
направление:
created: ГГГГ-ММ-ДД
source: мое решение
status: гипотеза
status_by: пользователь
tags:
  - "#агент"
---

# <имя>

## Роль
Ты <имя>. Имя в полях for и from: <имя>. <Что делает агент, одно-два предложения.>

## Источники
<Откуда агент берет данные, если не только из хранилища.>

## Скиллы
<Только скиллы этого агента. Общие скиллы подключает agent-run.>

## Реестр
00-atlas/agents/<имя>-реестр.md

## Запуск
1. Вызови скилл agent-run и выполни его раздел «Запуск».
2. <Что делать без заданий: фоновая работа или завершение.>

## <Разделы работы агента>

## Запреты
<Только запреты этого агента. Общие запреты в agent-run.>

## Связи
| Глагол | Цель | Примечание |
| --- | --- | --- |
| описан_в | [[агент <имя>]] | техническая карточка |
````

Разделы «Источники» и «Реестр» ставятся, только если они нужны агенту. Образец карточки с разделом «Источники»: [шаблон карточки агента нетворкер](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20%D0%BA%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B8%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%B0%20%D0%BD%D0%B5%D1%82%D0%B2%D0%BE%D1%80%D0%BA%D0%B5%D1%80.md).

Статус карточки: «гипотеза» до развертывания, «решение» после приемки. Статус меняет только пользователь.

## Шаги

1. Придумайте роль и имя агента. Русское имя нужно для файлов и заметок, латинское для юнитов и скриптов. Латинское имя фиксируется сразу.

2. Напишите карточку 00-atlas/agents/<имя>.md по разделу «Карточка агента». Имя файла проверьте скиллом naming-check. [obsidian]

3. Если агенту нужна фоновая инкрементальная работа, добавьте в карточку раздел «Реестр». Правило «реестра нет - создай пустой» задает скилл agent-run. [obsidian]

4. Создайте техническую карточку в инфраструктуре: 03-areas/infrastructure/агент <имя>.md, по образцу «агент нетворкер»: таблица компонентов (промпт, реестр, скрипт, path unit, service, cron, лог, блокировка, модель, инструменты), логика запуска, формат задания, команды проверки. В карточке агента эта связь стоит строкой «описан_в». [obsidian]

5. Если агенту нужны скиллы, которых нет, поставьте задание методисту на создание скилла в 06-inbox/tasks/. Не создавайте скиллы в обход методиста: скилл - это контракт, изменение которого без версии ломает поставленные задания. Новый скилл получает `skill_status: черновик`, а агенты применяют только скиллы со статусом «действует». Для боевой работы переведите скилл в «действует» или прямо потребуйте этот статус в задании методисту. Подробно: [12-скиллы и методист](12-%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D1%8B%20%D0%B8%20%D0%BC%D0%B5%D1%82%D0%BE%D0%B4%D0%B8%D1%81%D1%82.md). [obsidian]

6. Создайте скрипт запуска /opt/second-brain/automation/scripts/run-<имя-латиницей>.sh по шаблону из [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md) (слой 3). Готовые образцы шести агентов: [скрипты запуска агентов](../scripts/%D1%81%D0%BA%D1%80%D0%B8%D0%BF%D1%82%D1%8B%20%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%B0%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2.md). Строка запуска передает карточку с текстовым префиксом:

   ```bash
   claude -p "Карточка агента: $(cat "00-atlas/agents/<имя>.md")" \
   ```

   Права 750, владелец brain. Префикс «Карточка агента:» обязателен: карточка начинается с YAML-блока, первая строка которого `---`, и без префикса аргумент claude -p начинается с дефисов, а разборщик командной строки принимает его за ключ. [сервер]

7. Создайте systemd path unit и service (`<имя-латиницей>-watch.path`, `<имя-латиницей>.service`) по шаблону из [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md) (слой 4). Сразу снимите лимит частоты запусков сервиса, иначе пачка событий в папке остановит path-юнит (разбор: [урок - лимит запусков systemd](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BB%D0%B8%D0%BC%D0%B8%D1%82%20%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%BE%D0%B2%20systemd.md)). Включите и проверьте:

   ```bash
   sudo mkdir -p /etc/systemd/system/<имя>.service.d
   printf '[Unit]\nStartLimitIntervalSec=0\n' | sudo tee /etc/systemd/system/<имя>.service.d/no-start-limit.conf > /dev/null
   sudo systemctl daemon-reload
   sudo systemctl enable --now <имя>-watch.path
   systemctl is-enabled <имя>-watch.path
   ls /etc/systemd/system/multi-user.target.wants/ | grep <имя>
   sudo systemctl cat <имя>.service | grep ExecStart
   ls -l $(sudo systemctl show <имя>.service -p ExecStart --value | sed -n 's/.*path=\([^ ;]*\).*/\1/p')
   ```

   Две последние команды сверяют путь ExecStart с реальным файлом скрипта: файл должен найтись. Если StartLimitIntervalSec=0 уже стоит в самом unit-файле сервиса, drop-in не нужен. Проверьте написание multi-user в разделе WantedBy: при опечатке юнит работает до перезагрузки и после нее молча не запускается. [сервер]

8. Добавьте страховочную строку в /etc/cron.d/second-brain-agents через блок cron в заметке [скрипты запуска агентов](../scripts/%D1%81%D0%BA%D1%80%D0%B8%D0%BF%D1%82%D1%8B%20%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%B0%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2.md), тот же скрипт. Время запуска разведите на минуту-другую с другими агентами. [сервер]

9. Если агент обрабатывает новые файлы inbox (как архивариус), до первого запуска создайте метку:

   ```bash
   sudo -u brain touch /home/brain/.last-run-<имя>
   ```

   Без нее первый прогон захватит всю историю файлов разом. [сервер]

10. Проведите приемку. Первое задание - «составь опись, ничего не меняй»: поставьте его заметкой в 06-inbox/tasks с `for: <имя>` и уникальным именем, например «приемка <имя>» [obsidian]. Проверьте запуск и лог на сервере [сервер]:

    ```bash
    sudo systemctl status <имя>.service
    pgrep -af claude
    tail -f /opt/second-brain/automation/logs/<имя>.log
    ```

    Проверьте отчет: агент исполнил задание по скиллу agent-run (отчет в 99-archive/tasks-done/reports/, задание в 99-archive/tasks-done/), ничего не изменил сверх задания. Боевые задания и автономную работу включайте только после чистой приемки.

11. После приемки переведите статус карточки агента в «решение». [obsidian]

12. Если агенту нужны более широкие права, используйте флаг `--settings <путь>` в его скрипте с отдельным файлом настроек. Проверьте тестом, что запреты (deny) из базового файла настроек не обходятся. Разбор: [урок - headless-агенты и разрешения](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20headless-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%80%D0%B0%D0%B7%D1%80%D0%B5%D1%88%D0%B5%D0%BD%D0%B8%D1%8F.md). [сервер]

Файлы index.md в 00-atlas/agents/ и 03-areas/infrastructure/ не правятся: по CLAUDE.md это заглушки папок, в них только YAML и фраза с названием папки.

## Чек-лист выхода

- [ ] `claude -p "какие правила знаешь?" --allowedTools Read` пересказывает CLAUDE.md из рабочего каталога агента
- [ ] строка запуска в скрипте начинается с `claude -p "Карточка агента: $(cat`
- [ ] path unit в состоянии active (waiting), юнит есть в `multi-user.target.wants`
- [ ] `systemctl show <имя>.service -p StartLimitIntervalUSec` дает `StartLimitIntervalUSec=0`
- [ ] путь в ExecStart сервиса совпадает с реальным файлом скрипта
- [ ] тест: заметка-задание в inbox, через секунды-десятки секунд она обработана, есть строка в реестре или отчет
- [ ] первая строка раздела отчета прогона: «agent-run <версия>»
- [ ] отчет по заданию лежит в `99-archive/tasks-done/reports/` с именем `<агент>-<ГГГГ-ММ-ДД>-<имя задания>-отчет.md`, в отчете фонового прогона о задании одна строка со ссылкой
- [ ] при очереди из нескольких заданий каждое получило свой отчет, а предложение по одному заданию не остановило остальные
- [ ] предложение агента написано по скиллу proposal-card: отдельный файл на задание, одна ссылка в шапке, два пустых раздела для пользователя
- [ ] холостой запуск (нет живых заданий) не вызывает claude: лог пуст, токены не потрачены
- [ ] строка cron добавлена и не совпадает по времени с другими агентами
- [ ] карточка агента: шапка с `type: агент`, раздел «Связи» таблицей, в тексте инструкций нет wiki-ссылок
- [ ] техническая карточка есть в 03-areas/infrastructure/
- [ ] приемка пройдена (первое задание - опись без изменений), статус карточки «решение»

## Что можно сделать не с сервера

Все шаги, работающие с содержимым хранилища, - обычные заметки Obsidian: карточка агента, реестр, техническая документация, постановка задания, чтение отчета. Их можно писать и править с телефона или ноутбука: синхронизация сама доставит изменения на сервер за секунды.

Терминал на сервере нужен только для того, что живет вне хранилища: скрипт запуска, systemd-юниты, crontab, файл-метка, `--settings` для расширенных прав и любая проверка «жив ли процесс, юнит, лог».
