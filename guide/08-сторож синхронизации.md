# 08. Сторож синхронизации (sync-watchdog)

Предыдущая: [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md). Следующая: [09-запуск claude code вручную](09-%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%20claude%20code%20%D0%B2%D1%80%D1%83%D1%87%D0%BD%D1%83%D1%8E.md).

## Зачем он нужен

Мост livesync-bridge узнает об изменениях через inotify - механизм событий файловой системы Linux. Он видит не все изменения:

- при перемещении каталога ядро выдает одно событие на сам каталог, событий на файлы внутри нет;
- файлы, созданные в обход обычной записи, могут не породить события.

В таком случае файлы лежат на диске, но в CouchDB их нет, и на устройствах они не видны. Сторож догоняет такие файлы автоматически, без участия человека и без затрат на API.

## Как работает

1. Читает метку времени /home/brain/.last-watchdog.
2. Находит все .md-файлы, измененные с прошлого прогона.
3. Выполняет по ним `touch`: обновляет время модификации. Для файлов, о которых мост уже знает, это холостая операция. Для перемещенных вместе с каталогом это недостающее событие.
4. Обновляет метку.

Метка обновляется после touch, поэтому только что обработанные файлы в следующий прогон не попадут. Зацикливания нет.

## Где что лежит

| Что | Где |
|---|---|
| Скрипт | /opt/second-brain/automation/scripts/sync-watchdog.sh |
| Метка | /home/brain/.last-watchdog |
| Права | владелец brain:secondbrain, права 750 |
| Расписание | crontab пользователя brain, каждые 10 минут |

Строка расписания (откройте crontab командой `sudo -u brain crontab -e`):

```
*/10 * * * * /opt/second-brain/automation/scripts/sync-watchdog.sh
```

Файл /opt/second-brain/automation/scripts/sync-watchdog.sh:

```bash
#!/bin/bash
# Догоняет файлы, о которых не узнал livesync-bridge:
# перемещения каталогов, файлы, созданные вне inotify.
STAMP=/home/brain/.last-watchdog
[ -f "$STAMP" ] || touch -d "1 hour ago" "$STAMP"

find /opt/second-brain/vault -name "*.md" -newer "$STAMP" \
  -not -path "*/.git/*" -not -path "*/.obsidian/*" \
  -not -path "*/06-inbox/*" \
  -exec touch {} +
touch "$STAMP"
```

Установка: создайте файл, затем выдайте владельца и права и проверьте ручным запуском:

```bash
sudo chown brain:secondbrain /opt/second-brain/automation/scripts/sync-watchdog.sh
sudo chmod 750 /opt/second-brain/automation/scripts/sync-watchdog.sh
sudo -u brain /opt/second-brain/automation/scripts/sync-watchdog.sh
ls -l --time-style=full-iso /home/brain/.last-watchdog
```

Признак успеха: файл-метка создан или обновлен. Первая строка скрипта обязана быть `#!/bin/bash`: при опечатке в интерпретаторе скрипт нельзя запустить напрямую, а cron вызывает его именно так.

## Исключения

- Каталоги .git/ и .obsidian/ служебные, синхронизировать их не нужно.
- Каталог 06-inbox/ сторож не трогает: за ним следит path unit агента. Лишний touch может запустить агента, а это платный вызов. Файлы в inbox живут недолго и попадают в мост обычным путем.

## Чего сторож не делает

- Не убирает устаревшие документы из CouchDB. Если файл перемещен вместе с каталогом, сторож зальет его по новому пути, но старый документ в CouchDB останется, и в Obsidian будут видны обе копии. Удаляйте старую копию в Obsidian, не на сервере: иначе мост восстановит файл обратно.
- Не отслеживает удаления. Файл, удаленный на сервере командой rm, останется в CouchDB и будет восстановлен. Удаляйте файлы только в Obsidian.
- Работает только с .md. Скрипты, изображения и прочее не трогает.
- Не лечит PermissionDenied на стороне моста. Сторож работает в одну сторону: файл на диске в CouchDB. Если мост не может записать файл на диск из-за чужого владельца каталога (направление CouchDB в файл), touch ничего не изменит. Лечение: исправьте владельца каталога. Разбор: [урок - права и владельцы в multi-user](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%80%D0%B0%D0%B2%D0%B0%20%D0%B8%20%D0%B2%D0%BB%D0%B0%D0%B4%D0%B5%D0%BB%D1%8C%D1%86%D1%8B%20%D0%B2%20multi-user.md).

## Проверка работы

Метка обновляется - значит, скрипт запускается:

```bash
ls -l --time-style=full-iso /home/brain/.last-watchdog
```

Ручной прогон:

```bash
sudo -u brain /opt/second-brain/automation/scripts/sync-watchdog.sh
```

Сколько раз за сутки запускался агент (не разбудил ли его сторож лишний раз):

```bash
sudo journalctl -u archivist --since "1 day ago" | grep Starting | wc -l
```
