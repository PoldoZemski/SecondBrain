# 05. Claude Code на сервере

Предыдущая: [04-мост в файлы (livesync-bridge)](04-%D0%BC%D0%BE%D1%81%D1%82%20%D0%B2%20%D1%84%D0%B0%D0%B9%D0%BB%D1%8B%20%28livesync-bridge%29.md). Следующая: [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md).

## Что ставим

Claude Code - программа Anthropic для командной строки. Она читает и пишет файлы и выполняет многошаговые задачи. В нашей системе она не работает постоянно: просыпается по событию или по расписанию, выполняет работу и завершается. Запускается без человека (флаг -p) от непривилегированного пользователя brain.

## Установка

Устанавливайте Claude Code через npm. Этот способ работает и в странах с ограничениями: сайт registry.npmjs.org доступен напрямую из РФ, а нативный установщик и бинарные релизы с GitHub недоступны. Обновление выполняется командой `npm update -g`.

Установите Node.js 20 от администратора:

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

Если apt спросит про перезапуск сервисов, выберите «none»: перезапуск Docker остановит контейнеры. Перезагрузку сервера выполните в плановое время.

Установите Claude Code от brain:

```bash
sudo -u brain -i
npm config set prefix ~/.npm-global
npm install -g @anthropic-ai/claude-code
export PATH=$HOME/.npm-global/bin:$PATH
echo 'export PATH=$HOME/.npm-global/bin:$PATH' >> ~/.bashrc
claude --version
```

Признак успеха: команда `claude --version` выводит номер версии.

## Аутентификация: только API-ключ

На сервере без браузера интерактивный вход недоступен. Единственный путь - ключ из console.anthropic.com (раздел API Keys). Это отдельный счет с оплатой по токенам. Сразу задайте месячный лимит расходов в консоли: пакетная обработка может быстро израсходовать баланс.

Создайте файл /home/brain/.env с правами 600:

```
ANTHROPIC_API_KEY=sk-ant-...
```

Загрузка ключа в сессию или скрипт:

```bash
set -a; . ~/.env; set +a
```

При первом запуске выполните `claude` интерактивно: пройдите мини-онбординг (тема, подтверждение ключа) и выйдите командой /exit. Если вы исправили опечатку в ключе, удалите файл ~/.claude.json и пройдите онбординг заново: в нем хранится одобрение конкретного ключа, и старое одобрение останавливает запуски без сообщения об ошибке.

## Канал к API из страны с блокировкой

Выполняйте этот раздел, только если сервер стоит в стране, где доступ к API нейросетей заблокирован. Проверка: прямой запрос возвращает код 403.

```bash
curl -s https://api.anthropic.com -o /dev/null -w "%{http_code}\n"
```

Что нужно: прокси-сервер в стране без ограничений (протокол VLESS с Reality) и клиент Xray на вашем VPS. Параметры подключения (адрес, порт, UUID, publicKey, shortId, serverName) выдает ваш прокси-сервер. Если с домашнего компьютера тот же прокси-сервер работает, а с VPS нет, смените адрес прокси-сервера или транспорт: трафик из дата-центров может подавляться оборудованием DPI. Разбор: [урок - dpi и протоколы туннелей](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20dpi%20%D0%B8%20%D0%BF%D1%80%D0%BE%D1%82%D0%BE%D0%BA%D0%BE%D0%BB%D1%8B%20%D1%82%D1%83%D0%BD%D0%BD%D0%B5%D0%BB%D0%B5%D0%B9.md).

##### Установка Xray

Официальный установочный скрипт ставит программу и службу systemd:

```bash
sudo bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
```

После установки файлы лежат здесь: программа /usr/local/bin/xray, настройки /usr/local/etc/xray/config.json, служба /etc/systemd/system/xray.service (запуск от пользователя nobody). Скрипт скачивает архив релиза с GitHub. Если с вашего сервера GitHub недоступен, список параметров скрипта (установка из локального файла, установка через прокси) выводит команда:

```bash
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ help
```

Документация: https://github.com/XTLS/Xray-install

##### Конфигурация

Два входа (inbound) с разным назначением, один выход (outbound) к вашему прокси-серверу. Замените значения в верхнем регистре данными прокси-сервера. Файл /usr/local/etc/xray/config.json:

```json
{
  "inbounds": [
    {
      "port": 10808,
      "listen": "127.0.0.1",
      "protocol": "socks",
      "settings": { "auth": "noauth", "udp": true }
    },
    {
      "port": 10809,
      "listen": "0.0.0.0",
      "protocol": "http",
      "settings": {}
    }
  ],
  "outbounds": [
    {
      "protocol": "vless",
      "settings": {
        "vnext": [
          {
            "address": "АДРЕС_ПРОКСИ_СЕРВЕРА",
            "port": 443,
            "users": [
              { "id": "UUID", "encryption": "none", "flow": "xtls-rprx-vision" }
            ]
          }
        ]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "serverName": "SNI_ИЗ_НАСТРОЕК_СЕРВЕРА",
          "fingerprint": "firefox",
          "publicKey": "PUBLIC_KEY",
          "shortId": "SHORT_ID"
        }
      }
    }
  ]
}
```

Порт 443 в примере замените портом вашего прокси-сервера. Блок streamSettings стоит внутри объекта outbound, рядом с settings. Значения serverName вставляйте чистым текстом, без разметки: ссылка вида `[имя](https://имя)` из копирования ломает рукопожатие.

Файл содержит ключи: права и владельца не меняйте на более открытые, в заметки его не копируйте.

Если прокси нужен только процессам на самом сервере, у входа 10809 поставьте `"listen": "127.0.0.1"` и пропустите шаг с файрволом ниже.

##### Порты Xray

| Порт | Протокол | Где слушает | Для кого |
|---|---|---|---|
| 10808 | SOCKS | 127.0.0.1 | программы на хосте, которые умеют только SOCKS |
| 10809 | HTTP | 0.0.0.0 (все интерфейсы) | Claude Code на хосте (через 127.0.0.1:10809) и контейнеры Docker (через адрес шлюза docker-сети) |

Порт 10809 доступен на всех интерфейсах, поэтому он обязан быть закрыт файрволом от интернета. Порядок обязателен: сначала правило файрвола, потом запуск с этим входом. Если оставить порт открытым без правила, сканеры находят открытый прокси за часы.

Узнайте подсеть docker-сети и разрешите доступ только ей:

```bash
sudo docker network inspect traefik_network --format '{{range .IPAM.Config}}{{.Subnet}}{{end}}'
sudo ufw allow from 172.19.0.0/16 to any port 10809 proto tcp
sudo ufw status numbered
```

Вместо 172.19.0.0/16 подставьте подсеть из вывода первой команды. Признак успеха: в списке правил порт 10809 разрешен только для этой подсети, строки с Anywhere для него нет. Xray работает на хосте, а не в контейнере, поэтому UFW его порты фильтрует (в отличие от портов контейнеров, см. [02-docker и traefik](02-docker%20%D0%B8%20traefik.md)).

##### Запуск и проверка

```bash
sudo /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
sudo systemctl enable --now xray
sudo ss -tlnp | grep -E 'xray|1080[89]'
```

Признаки успеха: проверка конфигурации сообщает «Configuration OK», в выводе ss строка 127.0.0.1:10808 и строка *:10809, у обеих процесс xray. Проверьте канал (порт 10809 с хоста):

```bash
curl -s --connect-timeout 15 --proxy http://127.0.0.1:10809 https://ifconfig.me
curl -s --connect-timeout 15 --proxy http://127.0.0.1:10809 https://api.anthropic.com -o /dev/null -w "%{http_code}\n"
```

Первая команда должна вернуть адрес вашего прокси-сервера, вторая код 404. Результат 404 означает, что канал работает: API отвечает. Результат 403 означает, что блокировка осталась. Результат 000 означает, что туннель не работает: смотрите журнал `sudo journalctl -u xray -n 30 --no-pager`.

Проверьте снаружи с устройства, не подключенного к серверу и его VPN, что порт 10809 закрыт (способ описан в главе [02-docker и traefik](02-docker%20%D0%B8%20traefik.md)).

##### Прокси для агентов и контейнеров

Агенты на хосте: укажите прокси в файле /home/brain/.env. Схема в адресе http, не https: при https curl пытается установить TLS с самим прокси, и рукопожатие рвется.

```
HTTPS_PROXY=http://127.0.0.1:10809
HTTP_PROXY=http://127.0.0.1:10809
NO_PROXY=localhost,127.0.0.1
```

Строка NO_PROXY обязательна: локальные обращения (CouchDB, вебхуки) не должны идти через туннель.

Агенты, которые читают российские сайты (нетворкер), выпускают домены .ru, .su и .рф мимо прокси: часть российских сайтов отказывает выходному узлу прокси за рубежом. Claude Code учитывает переменную NO_PROXY, домены с точкой в начале покрывают все поддомены. Строки в скрипте такого агента, после загрузки .env:

```bash
export NO_PROXY="${NO_PROXY:+$NO_PROXY,}.ru,.su,.xn--p1ai"
export no_proxy="$NO_PROXY"
```

API Anthropic и t.me при этом идут через прокси. Проверка, нужно ли это вашему агенту: сравните ответ сайта через прокси и напрямую.

```bash
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:10809 --max-time 15 https://www.rusprofile.ru
curl -s -o /dev/null -w '%{http_code}\n' --max-time 15 https://www.rusprofile.ru
```

Если через прокси 403, а напрямую 200, сайту нужен прямой выход.

Контейнеры: внутри контейнера 127.0.0.1 - это сам контейнер, поэтому они обращаются к хосту по адресу шлюза docker-сети (в нашей схеме 172.19.0.1). Адрес шлюза показывает команда:

```bash
sudo docker network inspect traefik_network --format '{{range .IPAM.Config}}{{.Gateway}}{{end}}'
```

В переменных контейнера укажите `HTTP_PROXY=http://ШЛЮЗ:10809` и `HTTPS_PROXY=http://ШЛЮЗ:10809`, а в NO_PROXY перечислите внутренние имена сервисов и CouchDB. Ловушки и проверки: [урок - сеть между хостом и контейнерами](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D1%81%D0%B5%D1%82%D1%8C%20%D0%BC%D0%B5%D0%B6%D0%B4%D1%83%20%D1%85%D0%BE%D1%81%D1%82%D0%BE%D0%BC%20%D0%B8%20%D0%BA%D0%BE%D0%BD%D1%82%D0%B5%D0%B9%D0%BD%D0%B5%D1%80%D0%B0%D0%BC%D0%B8.md).

```bash
cd /opt/second-brain/vault

```

## Политика инструментов

- Для работы с файлами выдавайте: Read, Glob, Grep, Write, Edit.
- Для перемещений и создания каталогов выдавайте точечно: Bash(mv:*), Bash(mkdir:*).
- Агенту, которому нужен интернет (нетворкер), выдавайте WebSearch и WebFetch. WebSearch платный по числу запросов, поэтому лимит запросов задайте в карточке агента.
- Команды rm и find не выдавайте. rm удаляет файлы, find умеет удалять через ключи -delete и -exec. Поиск файлов покрывает инструмент Glob. Агент физически не может удалять файлы: удаление заменяется перемещением в архив, это обратимо.
- Запускам без человека задавайте `--permission-mode acceptEdits`. Без него Write и Edit молча ждут подтверждения, которого некому дать.
- Файл CLAUDE.md в корне рабочего каталога читается автоматически. Положите туда устав базы знаний, и он действует на всех агентов.
- Инструмент Edit создает новые файлы, а не только правит существующие. Поэтому исключение Write из списка не запрещает агенту создавать файлы. Надежная защита от необратимых действий - отсутствие rm. Разбор: [урок - headless-агенты и разрешения](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20headless-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%80%D0%B0%D0%B7%D1%80%D0%B5%D1%88%D0%B5%D0%BD%D0%B8%D1%8F.md).
