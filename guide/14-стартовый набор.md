# 14. Стартовый набор: устав, скиллы и шесть агентов

Предыдущая: [13-инструкция для помощника по серверу](13-%D0%B8%D0%BD%D1%81%D1%82%D1%80%D1%83%D0%BA%D1%86%D0%B8%D1%8F%20%D0%B4%D0%BB%D1%8F%20%D0%BF%D0%BE%D0%BC%D0%BE%D1%89%D0%BD%D0%B8%D0%BA%D0%B0%20%D0%BF%D0%BE%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D1%83.md). Следующая: [15-резервные копии и обслуживание](15-%D1%80%D0%B5%D0%B7%D0%B5%D1%80%D0%B2%D0%BD%D1%8B%D0%B5%20%D0%BA%D0%BE%D0%BF%D0%B8%D0%B8%20%D0%B8%20%D0%BE%D0%B1%D1%81%D0%BB%D1%83%D0%B6%D0%B8%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5.md).

Главы 01-06 дают сервер, синхронизацию и механизм запуска агентов. Эта глава дает то, что агент читает при запуске: устав хранилища (CLAUDE.md), 18 скиллов и карточки шести агентов: секретаря, архивариуса, методиста, библиотекаря, нетворкера и бизнес-аналитика. После нее система работает: вы пишете задачу в карточке, секретарь переносит ее в общий список, архивариус разбирает входящие, нетворкер ведет карточки людей и компаний, методист следит за скиллами, библиотекарь за ссылками и именами.

Все файлы набора - шаблоны с плейсхолдерами в угловых скобках. Они лежат в папке `starter/` этого гайда. Скиллы типов карточек и стиля даны в сокращенном виде: они задают структуру и правила, которые вы расширяете под свою практику.

## Шаги

### 1. Структура папок

Создавайте папки в Obsidian, а не командой mkdir на сервере: пустые папки с сервера на устройства не приезжают ([урок - пустые папки не синхронизируются](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%83%D1%81%D1%82%D1%8B%D0%B5%20%D0%BF%D0%B0%D0%BF%D0%BA%D0%B8%20%D0%BD%D0%B5%20%D1%81%D0%B8%D0%BD%D1%85%D1%80%D0%BE%D0%BD%D0%B8%D0%B7%D0%B8%D1%80%D1%83%D1%8E%D1%82%D1%81%D1%8F.md)). В каждой папке создайте заметку `index.md` с таким текстом (подставьте имя папки и дату):

```markdown
---
created: ГГГГ-ММ-ДД
source: мое решение
tags:
  - structure
---

Служебная заметка папки <имя папки>. Не удалять: без файла папка не синхронизируется на устройства.
```

Папка 99-archive/skills-retired и вложенные папки 99-archive и 00-atlas/agents/skills в заглушках не нуждаются, но лишний index.md в них безвреден.

### 2. Устав CLAUDE.md

Создайте в корне хранилища заметку CLAUDE.md (имя файла в верхнем регистре). Скопируйте в нее текст из [шаблон claude.md](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20claude.md%2C%20%D1%87%D0%B0%D1%81%D1%82%D1%8C%201.md), затем добавьте в конец текст из [шаблон claude.md, часть 2](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20claude.md%2C%20%D1%87%D0%B0%D1%81%D1%82%D1%8C%202.md). Замените плейсхолдеры: язык заметок, свои папки, закрытые от агентов данные. Первая строка файла - заголовок «База знаний: правила работы», YAML-шапки у CLAUDE.md нет.

### 3. Скиллы

Для каждого шаблона скилла из таблицы создайте папку с именем скилла (kebab-case латиницей) и в ней заметку SKILL.md. Скопируйте текст из блока шаблона. Замените `<ВАШЕ ИМЯ>` и `ГГГГ-ММ-ДД`. Всего 18 папок: agent-run, task-card, task-report, proposal-card, yaml-frontmatter, naming-check, entity-relations, skill-maintenance, str, source-extract, contact-card, org-card, place-card, concept-card, idea-card, process-card, client-card, project-card.

У скилла naming-check есть второй файл, скрипт проверки: создайте его на сервере (Obsidian файлы .py не показывает):

```bash
sudo -u brain mkdir -p /opt/second-brain/vault/00-atlas/agents/skills/naming-check/scripts
sudo -u brain nano /opt/second-brain/vault/00-atlas/agents/skills/naming-check/scripts/check-names.py
```

Вставьте текст из шаблона [шаблон скилла naming-check](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%B0%20naming-check.md), сохраните (Ctrl+O, Enter, Ctrl+X) и проверьте:

```bash
sudo -u brain python3 /opt/second-brain/vault/00-atlas/agents/skills/naming-check/scripts/check-names.py
```

Признак успеха: последняя строка вывода `Всего нарушений: N`.

### 5. Карточки агентов

Создайте заметки в `00-atlas/agents/` из шаблонов: секретарь, архивариус, методист, библиотекарь, нетворкер. Нетворкеру нужен доступ в интернет и модель уровня sonnet; карта источников по желанию, без нее он ищет только платным WebSearch с лимитом (см. шаблон [шаблон карточки агента нетворкер](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20%D0%BA%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B8%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%B0%20%D0%BD%D0%B5%D1%82%D0%B2%D0%BE%D1%80%D0%BA%D0%B5%D1%80.md)). Карточку бизнес-аналитика создавайте, если вам нужен разбор транскриптов и документов клиентов: она требует рабочей папки `/opt/second-brain/work/` (шаблон описывает ее структуру).

### 6. Скрипты и расписание на сервере

Создайте каталоги и извлеките пять скриптов из заметки [скрипты запуска агентов](../scripts/%D1%81%D0%BA%D1%80%D0%B8%D0%BF%D1%82%D1%8B%20%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%B0%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2.md). Команды от администратора:

```bash
sudo -u brain mkdir -p /opt/second-brain/automation/scripts /opt/second-brain/automation/logs
NOTE="/opt/second-brain/vault/04-resources/guides/second-brain/scripts/скрипты запуска агентов.md"; for s in run-archivist run-methodologist run-secretary run-librarian run-networker; do sudo -u brain awk -v s="$s" '$0=="```bash " s ".sh"{f=1;next} /^```$/{f=0} f' "$NOTE" > /tmp/$s.sh; [ -s /tmp/$s.sh ] && bash -n /tmp/$s.sh && echo "OK $s" || echo "ОШИБКА $s"; done
```

Заметка со скриптами лежит в вашем хранилище только если вы скопировали туда гайд. Если нет, создайте скрипты вручную из блоков заметки. В скрипте нетворкера проверьте идентификатор модели во флаге `--model` и строки NO_PROXY: они нужны, только если сервер ходит в интернет через прокси.

Если вывод пять строк `OK`, установите скрипты и расписание:

```bash
for s in run-archivist run-methodologist run-secretary run-librarian run-networker; do sudo install -o brain -g secondbrain -m 750 /tmp/$s.sh /opt/second-brain/automation/scripts/$s.sh; done
NOTE="/opt/second-brain/vault/04-resources/guides/second-brain/scripts/скрипты запуска агентов.md"; sudo awk '$0=="```cron second-brain-agents"{f=1;next} /^```$/{f=0} f' "$NOTE" | sudo tee /etc/cron.d/second-brain-agents > /dev/null
sudo chmod 644 /etc/cron.d/second-brain-agents
cat /etc/cron.d/second-brain-agents
ls -l /opt/second-brain/automation/scripts/
```

Признак успеха: в `cron.d` пять строк запуска (минуты 7, 19, 31, 43 каждый час и строка нетворкера раз в неделю по понедельникам), в списке скриптов пять `run-*.sh` и `vault-commit.sh`, владелец brain, права 750.

Добавьте в crontab пользователя brain недельные задачи (`sudo -u brain crontab -e`):

```
0 8 * * 1 /opt/second-brain/automation/scripts/run-librarian.sh full
0 10 * * 1 /opt/second-brain/automation/scripts/run-methodologist.sh --weekly-review
0 * * * * /opt/second-brain/automation/scripts/vault-commit.sh
*/10 * * * * /opt/second-brain/automation/scripts/sync-watchdog.sh
```

Режим `full` библиотекаря запускает еженедельную полную проверку, `--weekly-review` методиста - обзор скиллов. Без этих строк обе работы не выполняются.

Агенты просыпаются по событию в папках 06-inbox через systemd path unit: unit-файлы и обязательная строка `StartLimitIntervalSec=0` описаны в главе [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md), слой 4. Для архивариуса, секретаря, методиста и библиотекаря path unit по желанию: часовой опрос cron тоже подхватит работу, с задержкой до часа. Нетворкеру path unit нужен обязательно: его cron запускается раз в неделю. Готовые unit-файлы нетворкера лежат в заметке со скриптами, раздел run-networker.sh.

Бизнес-аналитик (по желанию): создайте его карточку и рабочую папку по инструкции в шаблоне [шаблон карточки агента бизнес-аналитик](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20%D0%BA%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B8%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%B0%20%D0%B1%D0%B8%D0%B7%D0%BD%D0%B5%D1%81-%D0%B0%D0%BD%D0%B0%D0%BB%D0%B8%D1%82%D0%B8%D0%BA.md) (скилл source-extract входит в набор). Затем установите скрипт `run-business-analyst.sh` по инструкции в разделе `run-business-analyst.sh` заметки со скриптами. Строка расписания: `*/15 * * * * /opt/second-brain/automation/scripts/run-business-analyst.sh` в crontab пользователя brain.

```markdown
Выполни раздел «Фоновая работа» своей карточки. Результат опиши в отчете.

## Как проверить результат
Отчет лежит в 99-archive/tasks-done/reports/, задание перемещено в 99-archive/tasks-done/.
```

3. Создайте любую карточку с разделом `## Следующие шаги` и строкой `- [ ] #todo проверочная задача`.
4. Запустите скрипт вручную:

```bash
sudo -u brain /opt/second-brain/automation/scripts/run-secretary.sh; echo "код выхода: $?"
```

Задание обработает секретарь (запуск займет от нескольких секунд до минуты).

5. Проверьте результат в Obsidian:
   - в `00-atlas/todo.md` появилась строка `- [ ] проверочная задача [[имя вашей карточки]]`;
   - в `99-archive/tasks-done/reports/` лежит отчет `секретарь-<дата>-сверить todo.md с карточками-отчет.md`;

   - в логе `/opt/second-brain/automation/logs/секретарь.log` есть запись о запуске;
   - в истории хранилища два снимка («до секретаря» и «после секретаря»):

```bash
sudo -u brain git --git-dir=/home/brain/vault.git log --oneline -n 5
```

8. Проверьте методиста: поставьте ему задание `проверить скиллы.md` (`for: методист`, раздел «Задание»: «Выполни раздел «Проверка скиллов» своей карточки. Ничего не правь, результат опиши в отчете»).
