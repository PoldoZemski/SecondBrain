# 15. Резервные копии и обслуживание

Предыдущая: [14-стартовый набор](14-%D1%81%D1%82%D0%B0%D1%80%D1%82%D0%BE%D0%B2%D1%8B%D0%B9%20%D0%BD%D0%B0%D0%B1%D0%BE%D1%80.md). Справочник по сбоям: [07-уроки проекта](07-%D1%83%D1%80%D0%BE%D0%BA%D0%B8%20%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D0%B0.md).

Снимки `vault-commit.sh` из главы [06-агенты и события](06-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B8%20%D1%81%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F.md) лежат на том же диске, что и сервер. Потеря сервера означает потерю базы CouchDB, истории git и секретов. Эта глава добавляет копию вне сервера, порядок восстановления и регулярное обслуживание.

## Что хранится где

| Данные | Где лежат | Копии |
|---|---|---|
| Заметки | на каждом устройстве с Obsidian, в CouchDB на сервере, файлами в /opt/second-brain/vault | устройства хранят полные копии, пока не очищены |
| История изменений хранилища | /home/brain/vault.git на сервере | только резервная копия из этой главы |
| Настройки и секреты | /opt/second-brain/.env, /home/brain/.env, config.json моста, config.json Xray | только резервная копия из этой главы |
| Сертификаты Traefik | /opt/stacks/traefik/letsencrypt/acme.json | резервная копия; без нее сертификаты выпускаются заново, что допустимо |

Правило: копия лежит вне сервера и зашифрована. Копия на том же сервере не защищает от потери сервера.

## Что копируется

В архив входят: каталог /opt/second-brain (compose-файл, .env, данные CouchDB, настройки моста, скрипты, рабочая папка work), файлы /home/brain/.env и /home/brain/vault.git, стек Traefik, настройки Xray, файл расписания агентов и текст crontab пользователя brain. Не входят: хранилище /opt/second-brain/vault (оно восстанавливается из CouchDB мостом), кэш Deno, node_modules моста, журналы агентов.

База CouchDB копируется при остановленных контейнерах: копия работающей базы может оказаться неконсистентной. Остановка длится меньше минуты, устройства досинхронизируются после запуска.

## Подготовка

Установите программы и создайте пароль шифрования (от администратора):

```bash
sudo apt install -y gnupg rclone
sudo sh -c 'umask 077; openssl rand -hex 32 > /root/.second-brain-backup-pass'
sudo cat /root/.second-brain-backup-pass
```

Сохраните выведенный пароль в менеджере паролей на другом устройстве. Без него копии не расшифровать: потеря сервера вместе с паролем делает копии бесполезными.

Настройте внешнее хранилище. Подойдет любое, которое поддерживает rclone: S3-совместимое облачное хранилище, SFTP на другой машине и другие. Интерактивная настройка (имя хранилища укажите `backup`):

```bash
sudo rclone config
sudo rclone lsd backup:
```

Признак успеха: вторая команда не выводит ошибку (список может быть пустым). Файл настроек /root/.config/rclone/rclone.conf содержит ключи доступа, права 600 выставляет сам rclone.

## Скрипт копирования

Создайте файл /usr/local/sbin/second-brain-backup.sh (владелец root, права 700). Замените `backup:second-brain` на ваше хранилище и каталог в нем. Если у вас нет Xray или файла расписания, удалите соответствующие строки из команды tar: tar останавливается на отсутствующем файле.

```bash
#!/bin/bash
# Резервная копия второго мозга: архив, шифрование, отправка вне сервера.
set -euo pipefail
export LC_ALL=C.UTF-8

COMPOSE=/opt/second-brain/compose.yml
LOCAL=/var/backups/second-brain
PASSFILE=/root/.second-brain-backup-pass
REMOTE="backup:second-brain"
KEEP_LOCAL_DAYS=14
KEEP_REMOTE_DAYS=60

STAMP=$(date +%F-%H%M)
ARCHIVE="$LOCAL/second-brain-$STAMP.tar.gz"
mkdir -p "$LOCAL"
chmod 700 "$LOCAL"

# Расписание агентов хранится в crontab пользователя brain: сохраняем его текстом.
crontab -u brain -l > /opt/second-brain/automation/crontab-brain.txt 2>/dev/null || true

# База CouchDB копируется только при остановленных контейнерах.
# Контейнеры запускаются снова при любом исходе, в том числе при ошибке.
trap 'docker compose -f "$COMPOSE" start >/dev/null 2>&1 || true' EXIT
docker compose -f "$COMPOSE" stop

tar -C / -czf "$ARCHIVE" \
  --exclude='opt/second-brain/vault' \
  --exclude='opt/second-brain/deno-cache' \
  --exclude='opt/second-brain/bridge-app/node_modules' \
  --exclude='opt/second-brain/automation/logs' \
  opt/second-brain \
  home/brain/.env \
  home/brain/vault.git \
  opt/stacks/traefik \
  usr/local/etc/xray/config.json \
  etc/cron.d/second-brain-agents

docker compose -f "$COMPOSE" start
trap - EXIT

gpg --batch --yes --pinentry-mode loopback --passphrase-file "$PASSFILE" \
  --symmetric --cipher-algo AES256 --output "$ARCHIVE.gpg" "$ARCHIVE"
rm -f "$ARCHIVE"

rclone copy "$ARCHIVE.gpg" "$REMOTE"

# Удаляются только старые копии из своего локального каталога и из каталога копий в хранилище.
find "$LOCAL" -name 'second-brain-*.tar.gz.gpg' -mtime +"$KEEP_LOCAL_DAYS" -delete
rclone delete "$REMOTE" --min-age "${KEEP_REMOTE_DAYS}d"
echo "OK $STAMP"
```

Каталог в хранилище должен быть отдельным и содержать только копии: команда `rclone delete` с параметром `--min-age` удаляет в нем все файлы старше указанного срока.

Права и первый запуск:

```bash
sudo chmod 700 /usr/local/sbin/second-brain-backup.sh
sudo /usr/local/sbin/second-brain-backup.sh
```

Признак успеха: последняя строка вывода `OK <дата>`, в хранилище появился файл:

```bash
sudo rclone ls backup:second-brain
```

Расписание (раз в сутки ночью, от root):

```bash
sudo crontab -e
```

Добавьте строку:

```
30 3 * * * /usr/local/sbin/second-brain-backup.sh >> /var/log/second-brain-backup.log 2>&1
```

## Проверка копии

Раз в месяц проверяйте, что последнюю копию можно расшифровать и прочитать. Подставьте имя файла из локального каталога:

```bash
sudo ls -l /var/backups/second-brain/
sudo gpg --batch --pinentry-mode loopback --passphrase-file /root/.second-brain-backup-pass -d /var/backups/second-brain/second-brain-ДАТА.tar.gz.gpg | tar -tzf - | head -20
```

Признак успеха: список файлов начинается с opt/second-brain. Копия, которую ни разу не пробовали читать, копией не считается.

## Восстановление после потери сервера

1. Подготовьте новый сервер по главам [01-подготовка vps и безопасность](01-%D0%BF%D0%BE%D0%B4%D0%B3%D0%BE%D1%82%D0%BE%D0%B2%D0%BA%D0%B0%20vps%20%D0%B8%20%D0%B1%D0%B5%D0%B7%D0%BE%D0%BF%D0%B0%D1%81%D0%BD%D0%BE%D1%81%D1%82%D1%8C.md) и [02-docker и traefik](02-docker%20%D0%B8%20traefik.md): система, пользователи brain (UID 1500) и admin_name, группа secondbrain (GID 1600), файрвол, Docker, сеть traefik_network. Номера пользователя и группы должны совпасть: архив хранит владельцев числами.
2. Установите rclone и gnupg, восстановите настройки хранилища (`sudo rclone config`) и пароль шифрования в файл /root/.second-brain-backup-pass из менеджера паролей.
3. Скачайте последнюю копию и расшифруйте ее в корень системы:

```bash
sudo rclone ls backup:second-brain
sudo rclone copy backup:second-brain/second-brain-ДАТА.tar.gz.gpg /root/
sudo gpg --batch --pinentry-mode loopback --passphrase-file /root/.second-brain-backup-pass -d /root/second-brain-ДАТА.tar.gz.gpg | sudo tar -xzf - -C /
```

4. Создайте каталоги, которых нет в архиве, с правами из глав 01 и 04:

```bash
sudo mkdir -p /opt/second-brain/vault /opt/second-brain/deno-cache /opt/second-brain/automation/logs
sudo chown -R brain:secondbrain /opt/second-brain/vault /opt/second-brain/deno-cache /opt/second-brain/automation/logs
sudo chmod -R 2775 /opt/second-brain/vault
```

5. Восстановите зависимости моста (слой 2 главы [04-мост в файлы (livesync-bridge)](04-%D0%BC%D0%BE%D1%81%D1%82%20%D0%B2%20%D1%84%D0%B0%D0%B9%D0%BB%D1%8B%20%28livesync-bridge%29.md): одноразовый контейнер `deno install`).
6. Направьте DNS-записи на адрес нового сервера. Запустите Traefik, затем систему:

```bash
sudo docker compose -f /opt/stacks/traefik/compose.yml up -d
sudo docker compose -f /opt/second-brain/compose.yml up -d
sudo docker logs second-brain-bridge --tail 50
```

Признак успеха: в логе моста волна строк `saved`, файлы появились в /opt/second-brain/vault.

7. Установите Xray по главе [05-claude code на сервере](05-claude%20code%20%D0%BD%D0%B0%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%B5.md) (конфиг уже восстановлен из архива) и включите службу. Затем верните расписание агентов:

```bash
sudo systemctl enable --now xray
sudo -u brain crontab /opt/second-brain/automation/crontab-brain.txt
sudo -u brain crontab -l
```

8. Выполните двусторонний тест из главы 04.

Сертификаты Traefik восстанавливаются из acme.json вместе с архивом. Если файла нет, Let's Encrypt выпустит их заново при первом обращении, пока DNS указывает на новый сервер.

## Если потеряна только база

Сервер жив, а база CouchDB повреждена или потеряна, устройства целы. Создайте новую пустую базу по главе [03-синхронизация obsidian](03-%D1%81%D0%B8%D0%BD%D1%85%D1%80%D0%BE%D0%BD%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20obsidian.md) и выполните на устройстве с полной актуальной копией хранилища операцию Rebuild/Overwrite remote. Остальные устройства затем делают Fetch. Это последний вариант: он перезаписывает базу содержимым одного устройства.

## Откат отдельного файла

Прежнюю версию файла хранилища читайте из истории git (раздел «Версионирование хранилища» главы 06). Резервная копия для этого не нужна: история лежит на сервере и обновляется каждый час.

## Обслуживание: регулярные проверки

### Раз в неделю

Резервная копия и опрос агентов работают:

```bash
sudo tail -n 3 /var/log/second-brain-backup.log
sudo rclone ls backup:second-brain | tail -n 3
sudo tail -n 20 /opt/second-brain/automation/logs/cron-опрос.log
```

Признак успеха: в журнале копий последняя строка `OK <свежая дата>`, в хранилище есть файл за последние сутки, в журнале опроса нет сообщений об ошибках (пустой журнал нормален).

### Раз в месяц

1. Обновите систему и проверьте, нужна ли перезагрузка:

```bash
sudo apt update && sudo apt upgrade -y
[ -f /var/run/reboot-required ] && echo "нужна перезагрузка" || echo "перезагрузка не нужна"
```

Перезагрузку выполняйте в плановое время командой `sudo reboot`. После нее проверьте, что все поднялось:

```bash
sudo docker ps
systemctl is-active fail2ban xray
sudo ufw status
sudo ss -tlnp
```

Признак успеха: все контейнеры в списке, службы `active`, лишних портов на 0.0.0.0 нет (допустимы 22, 80, 443, 10809 при схеме с Xray).

2. Сделайте ручную копию и проверку из раздела «Проверка копии», если за месяц менялась архитектура.

3. Проверьте открытые порты и работающие службы. Ненужную службу остановите и отключите ([урок - лишние службы занимают память](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BB%D0%B8%D1%88%D0%BD%D0%B8%D0%B5%20%D1%81%D0%BB%D1%83%D0%B6%D0%B1%D1%8B%20%D0%B7%D0%B0%D0%BD%D0%B8%D0%BC%D0%B0%D1%8E%D1%82%20%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D1%8C.md)):

```bash
systemctl list-units --type=service --state=running
df -h
free -h
sudo docker system df
```

4. Обновите Claude Code и проверьте версию:

```bash
sudo -u brain -H bash -lc 'npm update -g @anthropic-ai/claude-code'
sudo -u brain -H bash -lc '~/.npm-global/bin/claude --version'
```

5. Проверьте баланс и месячный лимит расходов в консоли Anthropic.

6. Обновите образы Docker по одному стеку. Перед этим сделайте копию: `sudo /usr/local/sbin/second-brain-backup.sh`.

```bash
sudo docker compose -f /opt/stacks/traefik/compose.yml pull
sudo docker compose -f /opt/stacks/traefik/compose.yml up -d
sudo docker compose -f /opt/second-brain/compose.yml pull
sudo docker compose -f /opt/second-brain/compose.yml up -d
sudo docker image prune -f
```

Команда `image prune -f` удаляет только образы без контейнеров и тегов, действующие сервисы не затрагивает. После обновления второго стека выполните двусторонний тест синхронизации из главы 04. Образ CouchDB закреплен на ветке 3, образы Traefik на ветке v3: не меняйте основную версию без отдельного плана и копии.

7. Сожмите историю хранилища:

```bash
sudo -u brain git --git-dir=/home/brain/vault.git gc
du -sh /home/brain/vault.git
```

### Раз в квартал

1. Проверьте сертификат домена синхронизации (подставьте свой домен):

```bash
echo | openssl s_client -connect sync.example.com:443 -servername sync.example.com 2>/dev/null | openssl x509 -noout -dates
```

Traefik продлевает сертификаты сам. Срок notAfter больше чем через 30 дней означает, что все в порядке.

2. Проверьте защиту SSH:

```bash
sudo fail2ban-client status sshd
```

3. Выполните полную пробную проверку восстановления на временном сервере или отдельном каталоге: расшифруйте копию, распакуйте и откройте ключевые файлы (compose, .env, config.json). Копия считается рабочей только после такой проверки.

4. Смените ключ API Anthropic и пароль CouchDB, если они где-то светились. Порядок смены пароля CouchDB описан в главе 03.

### Журналы

Журналы агентов и копий растут без ограничения. Создайте файл /etc/logrotate.d/second-brain:

```
/opt/second-brain/automation/logs/*.log /var/log/second-brain-backup.log {
    weekly
    rotate 8
    compress
    missingok
    notifempty
    copytruncate
}
```

Проверьте без применения: `sudo logrotate -d /etc/logrotate.d/second-brain`. Признак успеха: вывод без слов error.

Журналы контейнеров ограничьте в compose-файле каждого сервиса и пересоздайте контейнер командой `up -d`:

```yaml
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```

### Автоматические обновления безопасности (по желанию)

```bash
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
```

Службы после таких обновлений могут перезапускаться. Перезагрузку система сама не выполняет, о ней напомнит файл /var/run/reboot-required.

### Смена версии системы

Не запускайте `do-release-upgrade` без отдельного плана. Смена версии Ubuntu - самостоятельная задача: свежая копия, проверка совместимости Docker, Node.js и Claude Code, проверка всех сервисов после перехода.
