# 11. Obsidian MCP для Claude Desktop

Предыдущая: [10-как завести нового агента](10-%D0%BA%D0%B0%D0%BA%20%D0%B7%D0%B0%D0%B2%D0%B5%D1%81%D1%82%D0%B8%20%D0%BD%D0%BE%D0%B2%D0%BE%D0%B3%D0%BE%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%B0.md). Следующая: [12-скиллы и методист](12-%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D1%8B%20%D0%B8%20%D0%BC%D0%B5%D1%82%D0%BE%D0%B4%D0%B8%D1%81%D1%82.md).

Главы 01-10 описывают сервер и агентов, которые работают без человека. Эта глава описывает другую половину системы: приложение Claude на вашем компьютере (чат, режим Cowork и вкладка Code), которому нужен доступ к тому же хранилищу Obsidian через движок самого приложения Obsidian: поиск с релевантностью, теги, обратные ссылки.

## Зачем это нужно

Мост к файлам хранилища (device bridge в Cowork) дает доступ к содержимому, но не видит структуру Obsidian: релевантность поиска, граф ссылок и список тегов по всему хранилищу там сводятся к обычному чтению файлов. Подключение через MCP-сервер плагина дает те же инструменты поиска, которые видите вы в Obsidian. Поиск по слову ставит нужную карточку на первое место с большим отрывом: это работа настоящего поискового движка, а не построчного grep.

## Что это такое

- Это не скиллы из папки 00-atlas/agents/skills/. Эти скиллы читают только агенты на сервере из текста запроса.
- Это не пакет kepano/obsidian-skills (скиллы формата markdown, bases и canvas для Claude Code). Его устанавливают отдельно.
- Это подключение к движку приложения Obsidian на вашем компьютере. Оно работает, только пока Obsidian открыт и хранилище загружено.

## Компоненты

| Компонент | Роль |
|---|---|
| Плагин Obsidian «Local REST API & MCP Server» (id obsidian-local-rest-api) | REST API и встроенный MCP-сервер (Streamable HTTP) поверх хранилища |
| mcp-remote (npm-пакет geelen/mcp-remote) | прокси stdio и http: превращает локальный процесс в клиента HTTP MCP-сервера |
| Расширение Claude Desktop в формате MCPB | оболочка, которую Claude Desktop умеет запускать (процесс node по stdio) |
| Claude Desktop Extensions (Settings, Extensions) | место установки: после установки инструменты доступны и в обычном чате, и в сессиях Cowork на этом устройстве |

## Почему нельзя просто указать url в манифесте

Спецификация MCPB (github.com/modelcontextprotocol/mcpb, файл MANIFEST.md) поддерживает только четыре типа сервера: node, python, binary и uv. Все они локальные и общаются с Claude Desktop через stdio. Типов http, url и sse в манифесте нет. Поэтому уже работающий HTTP MCP-сервер заворачивают в локальный stdio-процесс через mcp-remote и упаковывают его как расширение типа node. Подробности: [урок - mcp-мост к локальному http-серверу](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20mcp-%D0%BC%D0%BE%D1%81%D1%82%20%D0%BA%20%D0%BB%D0%BE%D0%BA%D0%B0%D0%BB%D1%8C%D0%BD%D0%BE%D0%BC%D1%83%20http-%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D1%83.md).

## Шаги установки

1. Включите и настройте плагин «Local REST API & MCP Server»: Settings, Community plugins, Local REST API. Скопируйте API key. [Obsidian на компьютере]

2. В том же разделе включите «Enable HTTP server» (порт 27123 по умолчанию, слушает только 127.0.0.1). На основном порту 27124 (https) у плагина самоподписанный сертификат, и Node без специального обхода его не принимает. Порт 27123 наружу не доступен, это штатная опция плагина для локальных клиентов. [Obsidian на компьютере]

3. Соберите расширение. Установите утилиту сборки и создайте каталог проекта:

```bash
npm install -g @anthropic-ai/mcpb
mkdir obsidian-vault-bridge && cd obsidian-vault-bridge
npm init -y
npm install mcp-remote
mkdir server
```

Создайте файлы manifest.json и server/index.js по разделу «Точная конфигурация» ниже. Затем проверьте и упакуйте:

```bash
mcpb validate manifest.json
mcpb pack . obsidian-vault-bridge.mcpb
```

Ключ и адрес объявлены полями user_config (ключ с флагом sensitive), а не зашиты в манифест: Claude Desktop сам спросит их при установке и хранит ключ в замаскированном виде. Проверенные версии: mcp-remote 0.8.1, @anthropic-ai/mcpb 2.1.2. [компьютер]

4. В Claude Desktop откройте Settings, Extensions и перетащите файл .mcpb в зону «Drag .MCPB or .DXT files here to install» (или нажмите «Install Extension»). Расширение не подписано (личная сборка), поэтому появится предупреждение: подтвердите установку вручную. [Claude Desktop]

5. При установке Claude Desktop спросит user_config: API key (вставьте ключ из шага 1) и адрес эндпоинта (по умолчанию уже стоит http://127.0.0.1:27123/mcp/, при стандартном порте из шага 2 менять не нужно).

6. Проверьте: в любой сессии Cowork на этом устройстве должны появиться инструменты расширения (vault_read, vault_write, vault_list, search_simple, search_query, tag_list). Вызовите легкий, например vault_list. Если первые вызовы падают по таймауту сразу после перезапуска Obsidian, подождите окончания переиндексации: [урок - таймаут сразу после перезапуска obsidian](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D1%82%D0%B0%D0%B9%D0%BC%D0%B0%D1%83%D1%82%20%D1%81%D1%80%D0%B0%D0%B7%D1%83%20%D0%BF%D0%BE%D1%81%D0%BB%D0%B5%20%D0%BF%D0%B5%D1%80%D0%B5%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%B0%20obsidian.md). [Cowork]

## Точная конфигурация

manifest.json:

```json
{
  "manifest_version": "0.3",
  "name": "obsidian-vault-bridge",
  "version": "1.0.0",
  "server": {
    "type": "node",
    "entry_point": "server/index.js",
    "mcp_config": {
      "command": "node",
      "args": ["${__dirname}/server/index.js", "${user_config.obsidian_url}"],
      "env": { "OBSIDIAN_API_KEY": "${user_config.obsidian_api_key}" }
    }
  },
  "user_config": {
    "obsidian_api_key": { "type": "string", "sensitive": true, "required": true },
    "obsidian_url": { "type": "string", "default": "http://127.0.0.1:27123/mcp/", "required": true }
  }
}
```

server/index.js:

```js
process.argv = [
  process.argv[0],
  require.resolve('mcp-remote/dist/proxy.js'),
  process.argv[2],                              // адрес из user_config.obsidian_url
  '--header', `Authorization:Bearer ${process.env.OBSIDIAN_API_KEY}`,
  '--transport', 'http-only',
];
require('mcp-remote/dist/proxy.js');
```

## Вкладка Code

Вкладке Code (Claude Code на вашем компьютере) обертка не нужна: ее MCP-клиент подключается к удаленным HTTP-серверам напрямую. Используйте основной https-порт 27124 как есть: ограничение с самоподписанным сертификатом относится только к Node внутри упаковки MCPB.

```bash
claude mcp add --transport http obsidian https://127.0.0.1:27124/mcp/ --header "Authorization: Bearer КЛЮЧ"
```

Обертка через mcp-remote нужна только для системы расширений Claude Desktop.

## Ограничения

- Расширение привязано к компьютеру (Claude Desktop этого устройства), а не к аккаунту. На другом устройстве повторите сборку и установку.
- Мост работает, только пока Obsidian открыт и хранилище загружено. Сразу после перезапуска Obsidian возможны первые таймауты: [урок - таймаут сразу после перезапуска obsidian](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D1%82%D0%B0%D0%B9%D0%BC%D0%B0%D1%83%D1%82%20%D1%81%D1%80%D0%B0%D0%B7%D1%83%20%D0%BF%D0%BE%D1%81%D0%BB%D0%B5%20%D0%BF%D0%B5%D1%80%D0%B5%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%B0%20obsidian.md).
- Один мост обслуживает одно хранилище: ключ и порт принадлежат конкретному экземпляру плагина. Для второго хранилища нужно отдельное расширение.
- Названия инструментов зависят от среды (например, mcp__remote-devices__obsidian-vault-bridge__vault_read или mcp__claude-device__lcl-obsidian-vault-bridge-vault_read). Если вызов по ожидаемому имени не находится, загрузите инструмент через поиск инструментов (ToolSearch) по имени, не угадывайте его.
- Один вызов записи пишет один файл. Для длинной карточки создайте короткую основу и дописывайте разделы отдельными вызовами. Массовые изменения (десятки и сотни файлов) через коннектор делайте скриптом на сервере: [урок - массовые изменения файлов только через сервер](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BC%D0%B0%D1%81%D1%81%D0%BE%D0%B2%D1%8B%D0%B5%20%D0%B8%D0%B7%D0%BC%D0%B5%D0%BD%D0%B5%D0%BD%D0%B8%D1%8F%20%D1%84%D0%B0%D0%B9%D0%BB%D0%BE%D0%B2%20%D1%82%D0%BE%D0%BB%D1%8C%D0%BA%D0%BE%20%D1%87%D0%B5%D1%80%D0%B5%D0%B7%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80.md).
- Не запускайте десятки чтений параллельно: читайте порциями по 3-4 вызова. Для чтения только шапки используйте точечное чтение поля, а не чтение всего файла.
- Если в очень длинном чате инструменты коннектора перестали загружаться, начните новый чат в том же проекте. Перезапуск Claude Desktop возвращает инструменты не в уже открытый чат.
- Не используйте vault_get_upload_url из облачной среды чата: адрес указывает на локальный компьютер, и вызов не завершается.
- Перед правкой карточки через vault_patch получите карту документа, после правки прочитайте результат. Правка метаданных переформатирует шапку, строка в начале раздела с таблицей ломает таблицу, уровни заголовков считаются от цели. Подробности: [урок - правка карточек через коннектор](../lessons/%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%80%D0%B0%D0%B2%D0%BA%D0%B0%20%D0%BA%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%B5%D0%BA%20%D1%87%D0%B5%D1%80%D0%B5%D0%B7%20%D0%BA%D0%BE%D0%BD%D0%BD%D0%B5%D0%BA%D1%82%D0%BE%D1%80.md).
