Создайте файл `00-atlas/agents/skills/yaml-frontmatter/SKILL.md` и скопируйте в него текст из блока. Замените `<ВАШЕ ИМЯ>` и `ГГГГ-ММ-ДД`. ````markdown
---
name: yaml-frontmatter
description: "Единые правила YAML-блока в начале каждой заметки: формат полей, тегов, списков, дат и ссылок, обязательные поля по типам. Читай перед созданием любой карточки."
metadata:
  author: <ВАШЕ ИМЯ>
  created: ГГГГ-ММ-ДД
  version: 1.0.0
  origin: derived
  skill_status: действует
---

# YAML-frontmatter: единый стандарт

## 1. Общие правила
- YAML-блок стоит в самом начале файла между строками `---`.
- Поле без значения оставляй пустым, не пиши «нет данных».
- Даты в YAML в формате ГГГГ-ММ-ДД. Даты в тексте заметки в формате ДД.ММ.ГГГГ.
- Wiki-ссылка в значении поля всегда в двойных кавычках: `task: "[[имя задания]]"`.
- Многословное текстовое значение (description и подобные) всегда в двойных кавычках, в одну строку.

## 2. Списки
Только блочный формат с дефисом, отступ 2 пробела. Инлайн-формат `[a, b]` не используется. Список из одного элемента тоже блочный.

```yaml
имя_поля:
  - значение1
  - значение2
```

## 3. Теги
Блочный список. Знак `#` и двойные кавычки не обязательны: записи `тег`, `"тег"` и `"#тег"` равнозначны. Недопустим только тег со знаком `#` без кавычек: YAML считает `#` началом комментария, тег теряется.

```yaml
tags:
  - тег1
  - "тег2"
```

## 4. Статус знания
Поле `status`: сырье | гипотеза | проверено | решение. Поле `status_by`: пользователь | агент. Значение «сырье» пишется с обычной буквой «е», без двух точек.

## 5. Тип заметки и направление
Поле `type` берется из закрытого списка: агент, task, proposal, отчет, контакт, организация, место, понятие, клиент, проект, идея, процесс, урок, ресурс, решение. Добавляйте свои типы по необходимости: одно значение на один тип заметки.

Поле `направление` содержит одну ссылку на карточку направления из 03-areas/ или пусто.

## 6. Обязательные поля по типам

Обычная заметка:

```yaml
---
type: ресурс
направление:
created: ГГГГ-ММ-ДД
source: внешний обзор | мое решение
status: гипотеза
status_by: агент
tags:
  - тег
---
```

Карточка агента:

```yaml
---
type: агент
created: ГГГГ-ММ-ДД
source: мое решение
status: гипотеза
status_by: пользователь
tags:
  - агент
---
```

Карточки контакта, организации, места, понятия, клиента, проекта, идеи и процесса: шапки описаны в скиллах этих типов. Задание, предложение и отчет: в скиллах task-card, proposal-card и task-report.

Заглушка папки index.md:

```yaml
---
created: ГГГГ-ММ-ДД
source: мое решение
tags:
  - structure
---
```

## 7. Шапка скилла
На верхнем уровне только `name`, `description`, `metadata`, при необходимости `allowed-tools`.

```yaml
---
name: <имя в kebab-case>
description: "<что делает скилл и когда его применять, одна строка>"
metadata:
  author: <имя>
  created: ГГГГ-ММ-ДД
  version: 1.0.0
  origin: derived
  skill_status: действует
---
```

`skill_status`: действует | черновик | устарел. Версия по semver: patch для формулировок, minor для новых правил, major для структурной переделки. Каждое изменение записывай новой строкой в раздел «История изменений».
