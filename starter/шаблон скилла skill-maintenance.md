# Skill-maintenance: управление скиллами

## Версионирование

Версия скилла имеет три части X.Y.Z.
- patch (Z): формулировки, опечатки, правила шапки, без изменения поведения.
- minor (Y): новое правило или раздел, обратно совместимо с выполненными заданиями.
- major (X): структурная переделка, ломает поставленные задания.

Каждое изменение повышает одно число: исправление 1.2.3 в 1.2.4, новое правило в 1.3.0, структурная переделка в 2.0.0. Если задание указывает версию, которая уже есть, скилл уже исправлен: запиши в отчет совпадение версий и дат.

## Структура скилла

Скилл занимает папку `00-atlas/agents/skills/<имя>/` с файлом `SKILL.md`.

Шапка:

```yaml
---
name: <имя скилла>
description: "<описание в двойных кавычках, одна строка>"
metadata:
  author: <имя автора>
  created: ГГГГ-ММ-ДД
  version: <X.Y.Z>
  origin: <derived | solution | captured | external>
  skill_status: <действует | черновик | устарел>
---
```

Поля:
- `name`: kebab-case латиницей, без пробелов.
- `description`: в двойных кавычках, одна строка.
- `metadata.created`: дата создания, не меняется.
- `metadata.version`: обновляется с каждым изменением.
- `metadata.origin`: derived (из инструкций), solution (новое решение), captured (из документации), external (внешний плагин).
- `metadata.skill_status`: действует (используется), черновик (не готов), устарел (выведен).

Содержание: заголовок `# <Название>`, основной текст, раздел `## История изменений` таблицей. Новая версия в верхней строке таблицы, версия совпадает с `metadata.version`, дата в формате ДД.ММ.ГГГГ, описание 1-2 предложения со ссылкой на задание или предложение.

## Правила изменения

- Одно задание правит один скилл. Исключение: задание прямо называет несколько скиллов. Проблему в другом скилле запиши в отчет и предложи отдельное задание.
- Предложения с решением пользователя выполняй раньше заданий: решение может вернуть отложенное задание в очередь.
- Перед исполнением проверь версию и историю: если скилл уже исправлен после создания задания, не переделывай работу.

## Создание нового скилла

1. Проверь имя скиллом naming-check.
2. Создай папку `00-atlas/agents/skills/<имя>/` (mkdir).
3. Создай SKILL.md: version 1.0.0, created сегодняшняя дата, `skill_status: черновик`, если задание прямо не требует «действует».
4. Напиши содержание с разделами и примерами.
5. Добавь первую строку истории: «1.0.0 | <дата> | Первая версия. Задание <имя>.»
6. Обнови карточку агента, который будет пользоваться скиллом.

Черновик - скилл не проверен пользователем, использует обсуждаемые правила или экспериментальный. Перевести из черновика в «действует» методист может только по явному заданию или решению пользователя.

## Вывод из употребления

1. Не удаляй скилл.
2. Перемести его в `99-archive/skills-retired/<имя>/`.
3. В архивной копии поставь `skill_status: устарел` и допиши последнюю версию: «Скилл выведен из употребления (причина). Заменен на <имя>.»
4. Удаление ссылок из карточек агентов делается отдельным заданием.

## Проверка целостности

Методист проверяет скиллы при каждом запуске:
1. В шапке есть name, description, metadata; description в двойных кавычках; поля author, created, version, origin, skill_status заполнены.
2. Версия совпадает с последней строкой истории.
3. История: таблица, версии X.Y.Z, даты ДД.ММ.ГГГГ, новая версия сверху.
4. Расхождения: скилл назван в карточке агента, а файла нет (внешний скилл - норма, внутренний - расхождение); скилл со статусом «черновик» или «устарел» назван в карточке агента; два скилла с похожими именами и содержанием.
5. Расхождения запиши в отчет. Без задания не исправляй. Нужна правка: оформи предложение.
