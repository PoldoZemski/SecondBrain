# Proposal-card: карточка предложения агента

## Правила

### Одна проблема, одно предложение
1. Один файл содержит одну проблему и один вопрос к пользователю.
2. Проблема встретилась в нескольких заданиях: напиши отдельное предложение на каждое задание, даже если проблема у них одна и та же. Пользователь решает по каждому отдельно.
3. Поле task одиночное: одно предложение ссылается не более чем на одно задание.
4. Предложение не заменяет отчет. Результат работы пиши в отчет по скиллу task-report. В предложении только вопрос и варианты.

### Имя файла
Образец: `<агент>-<суть вопроса>-<ГГГГ-ММ-ДД>.md`. Для предложения по заданию суть вопроса - имя задания, при необходимости сокращенное. Файл с таким именем уже есть в 06-inbox/proposals/ или в 99-archive/proposals-done/: добавь в конец имени `-2`, затем `-3`. Имя проверь скиллом naming-check.

### YAML-шапка

```yaml
---
type: proposal
from: <имя агента>
created: ГГГГ-ММ-ДД
proposal_status: ждет решения
task: "[[имя задания]]"
tags:
  - "предложение"
---
```

Поле task ставь, если предложение возникло при исполнении задания. Поле previous ставь только в предложении-замене. Формат полей, ссылок и тегов по скиллу yaml-frontmatter. Значение proposal_status агент пишет только одно: «ждет решения».

### Разделы файла

```markdown
# Предложение: <суть вопроса>

## Контекст
2-4 предложения: откуда взялся вопрос, ссылка на задание.

## Проблема
Что именно неясно или не получается. Факты с путями к файлам.

## Варианты
### Вариант А (рекомендуемый)
Конкретное действие: какие файлы меняются и как.
### Вариант Б
Конкретное действие.

## Решение пользователя

## Комментарий пользователя
```

Правила разделов:
1. Варианты помечай буквами А, Б, В. Каждый описывает конкретное действие. Агент исполнит одобренный вариант буквально.
2. Рекомендуемый вариант помечай словом «(рекомендуемый)». Один вариант всегда «оставить как есть».
3. Разделы «Решение пользователя» и «Комментарий пользователя» создай пустыми. В них пишет только пользователь.
4. Как агент читает решение, описано в CLAUDE.md, раздел «Предложения агентов».

### Предложение-замена после отклонения
Пользователь отклонил предложение и написал комментарий: агент пишет новое предложение. Отличия:
1. Новый файл с новым именем. Старое предложение не правь.
2. В шапке поле `previous: "[[имя отклоненного предложения]]"`. Поле task то же, что у старого.
3. Раздел «Контекст» начинается с комментария пользователя дословно, одним абзацем. Затем 1-2 предложения о том, что учтено.
4. Не повторяй отклоненные варианты.

### Запреты
1. Не ставь proposal_status «одобрено» или «отклонено».
2. Не пиши в разделы пользователя.
3. Не объединяй несколько заданий в одно предложение.
4. Не жди ответа: после записи предложения переходи к следующему заданию или завершай работу.
