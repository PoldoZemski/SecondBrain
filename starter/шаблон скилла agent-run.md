# Agent-run: общий порядок запуска агента

## Раздел «Запуск»

1. Прочитай CLAUDE.md. Его правила действуют без исключений.
2. Имя агента указано в разделе «Роль» его карточки. Это имя стоит в полях for и from.
3. Найди в 06-inbox/proposals/ предложения с `from: <имя>` и решением пользователя в proposal_status. Регистр значения не важен. Обрабатывай каждое предложение отдельно: исполни и закрой по CLAUDE.md, раздел «Предложения агентов». Исполнение запиши в отчет по этому предложению (раздел «Отчеты»). Порядок закрытия: сначала допиши раздел «Итог» в файл предложения прямо в 06-inbox/proposals/, затем перемести этот файл одной командой `mv -n` в 99-archive/proposals-done/. Не копируй файл через Write или cp и не удаляй оригинал командой rm: эти команды агенту недоступны, а копия оставит оригинал в 06-inbox/proposals/, и скрипт запуска будет вызывать агента по нему при каждом опросе. В 99-archive/proposals-done/ уже есть файл с таким именем: не перезаписывай его, опиши ситуацию в отчете. После перемещения проверь, что в 06-inbox/proposals/ этого файла больше нет. Файл остался на месте: запиши это в отчет, раздел «Проблемы и трудности».
4. Найди в 06-inbox/tasks/ задания с `type: task` и `for: <имя>`. См. CLAUDE.md, раздел «Папка заданий» - порядок исполнения, поле after и task_status. Исполняй их по разделу «Очередь заданий». Пункт 3 идет раньше, потому что решение по предложению может вернуть отложенное задание в очередь.
5. Вернись к разделу «Запуск» карточки агента. Карточка задает, что делать дальше: фоновая работа или завершение.

Агент, который не берет заданий из 06-inbox/tasks/, пропускает пункты 3-4 этого раздела. Карточка такого агента говорит об этом сама.

## Раздел «Очередь заданий»

1. В одном сеансе можно исполнить несколько заданий, но строго по одному, в порядке возрастания created. Заканчивай каждое задание полностью (отчет, архив, реестр), потом бери следующее.
2. Каждое задание получает свой отчет по скиллу task-report. Один отчет на несколько заданий запрещен. Отчет по заданию не дублируй в отчете фонового прогона.
3. По заданию нужно решение пользователя: напиши предложение по скиллу proposal-card только по этому заданию, поставь заданию `task_status: ждет решения` и переходи к следующему заданию. Одно предложение на несколько заданий запрещено, даже если проблема у них одна и та же.
4. Неясность в одном задании не блокирует остальные.
5. Перемещай задание в 99-archive/tasks-done/ только после полного завершения. Объемное задание не архивируй раньше срока (CLAUDE.md, раздел «Папка заданий» - самовозобновляемая работа).
6. Перемещай задание в архив только командой `mv -n`: она не перезаписывает существующий файл. Перед перемещением проверь, нет ли в 99-archive/tasks-done/ файла с тем же именем. Есть: перемести задание под именем `<имя задания>-<ГГГГ-ММ-ДД>.md`, в ссылке на задание в отчете укажи новое имя и запиши совпадение в отчет. После перемещения проверь, что в 06-inbox/tasks/ файла больше нет.
7. Задание называет версию скилла, а действующая версия другая: исполняй по действующей, расхождение запиши в отчет.

## Раздел «Вложения»

Задание или заметка ссылается на файл вставкой `![[имя]]` или ссылкой `[[имя]]` без пути. Obsidian находит такой файл по имени в любой папке хранилища. Чаще всего вставленные картинки лежат в корне хранилища.

1. Ищи файл по имени во всем хранилище, а не только в папке задания: инструмент Glob с шаблоном `**/<имя>`.
2. Нашелся один файл: открой его инструментом Read. Изображение читай сам: имена, телефоны, ники, даты, подписи.
3. Нашлось несколько файлов с таким именем: возьми файл из папки задания, иначе из корня хранилища. Какой файл взят, запиши в отчет.
4. Файл не нашелся во всем хранилище: исполни задание без него и запиши имя файла в отчет, раздел «Что не сделано и почему». Предложение из-за этого не пиши.
5. Сведения из вложения противоречат тексту задания: верным считай вложение, если это скриншот профиля или документа. Расхождение запиши в отчет.

## Раздел «Отчеты»

Агент пишет отчеты трех видов. Не смешивай их.

1. Отчет по заданию: `99-archive/tasks-done/reports/<агент>-<ГГГГ-ММ-ДД>-<имя задания>-отчет.md`. Пиши по скиллу task-report. Один отчет на одно задание.
2. Отчет по исполненному предложению: `99-archive/tasks-done/reports/<агент>-<ГГГГ-ММ-ДД>-<имя предложения>-отчет.md`. Пиши по скиллу task-report. Один отчет на одно предложение.
3. Отчет фонового прогона: `99-archive/tasks-done/cron-reports/<агент>-<ГГГГ-ММ-ДД>.md`. Правила в разделе «Отчет фонового прогона».

Исполнение задания или предложения описывай только в отчете по нему. Результаты задания в cron-reports/ не пиши. Результаты фоновой работы в reports/ не пиши.

## Раздел «Отчет фонового прогона»

1. Путь: `99-archive/tasks-done/cron-reports/<имя>-<ГГГГ-ММ-ДД>.md`.
2. Пиши в отчет только фоновую работу по карточке агента. Задания и предложения, исполненные в этом прогоне, отмечай одной строкой на каждое: `- задание [[имя задания]]: [[имя отчета]]` или `- предложение [[имя предложения]]: [[имя отчета]]`. Детали по ним не повторяй.
3. Новый файл начинается с YAML-шапки:

```yaml
---
type: отчет
created: ГГГГ-ММ-ДД
source: агент-<имя>
tags:
  - "отчет"
---
```

4. Файл за эту дату уже есть: допиши раздел с временем прогона. Прошлые отчеты не перезаписывай и не удаляй.
5. Первая строка каждого раздела: «agent-run <версия>». По этой строке пользователь видит, что агент загрузил скилл.
6. Обязательные разделы: «Проблемы и трудности», «Предложения по улучшению». Пусто: напиши «нет». В прогоне была только работа по заданиям, фоновой работы нет: напиши «Фоновая работа: нет».

## Раздел «Реестр»

Правило действует, если карточка агента называет реестр.

1. Путь: `00-atlas/agents/<имя>-реестр.md`. Реестра нет: создай пустой.
2. Каждый обработанный элемент записывай в реестр сразу, одной строкой: путь, дата, результат.

## Раздел «Общие скиллы»

1. **yaml-frontmatter**: любой YAML-блок.
2. **naming-check**: имя каждого нового файла перед созданием.
3. **str**: любой текст заметки.
4. **task-report**: отчет по заданию и по исполненному предложению.
5. **proposal-card**: любое предложение пользователю.
6. **obsidian-markdown**: ссылки, вставки, callout-блоки. Это внешний скилл плагина Claude Code, он ставится отдельно.
7. Применяй только скиллы со значением `skill_status: действует`. Скилл со значением «черновик» применяй, только если задание прямо его называет.
8. Скилл obsidian-cli на сервере неприменим: он требует запущенного приложения Obsidian. Работай с файлами хранилища напрямую.

## Раздел «Общие запреты»

1. Не правь 00-atlas/agents/skills/. Исключение: методист по заданию или по своему одобренному предложению, CLAUDE.md пункт 6.
2. Не правь карточки агентов, CLAUDE.md, файлы index.md.
3. Не создавай файлы в 00-atlas/agents/, кроме своего реестра.
4. Ситуация неоднозначна: не действуй по этому заданию. Опиши вопрос в отдельном предложении по скиллу proposal-card, одно предложение на одно задание, и переходи к следующему заданию. Отчет сам по себе вопрос пользователю не доносит.
5. Раздел «Связи» карточки агента служит пользователю. Не открывай заметки из этого раздела, если задание прямо этого не требует.
6. Не меняй поле proposal_status. Его меняет только пользователь.
