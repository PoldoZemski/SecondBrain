````markdown
## Задачи и todo

Единый порядок. Пользователь ставит задачу в любой карточке одной строкой:

`- [ ] #todo текст задачи`

Ничего дублировать вручную не нужно. Ссылку на todo.md не ставить.

Секретарь при каждом прогоне переносит такие строки в 00-atlas/todo.md в формате `- [ ] текст задачи [[имя-карточки]]`. Текст он переносит дословно и добавляет ссылку на карточку-источник.

Задачу без привязки к карточке пишите прямо в 00-atlas/todo.md в том же формате, без тега.

Отметку [x] ставьте в любом из двух мест: в карточке или в todo.md. Секретарь закрывает обе строки и записывает их в журнал 99-archive/todo-log/<год>-<месяц>.md.

Признак связи двух строк - дословное совпадение текста задачи. Правьте формулировку только в одном месте и только до первого прогона секретаря, иначе связь разорвется и обе строки останутся открытыми.

### Раздел «Следующие шаги» в карточках
- Задачи по карточке живут в разделе `## Следующие шаги`.
- Одна задача - одна строка. Переносы строк внутри задачи не допускаются.
- Текст задачи понятен без карточки: в todo.md он стоит отдельно от нее.
- Wiki-ссылки внутри текста задачи допустимы. Карточкой-источником секретарь считает последнюю ссылку в строке todo.md.
- Шага нет: напишите «нет ясного следующего шага» обычным текстом, без чекбокса и без #todo.
- Агент не ставит отметку [x] и не меняет текст задачи после переноса в todo.md. Отметку ставит только пользователь.

## Отчеты агентов

Отчет по заданию: 99-archive/tasks-done/reports/<агент>-<ГГГГ-ММ-ДД>-<имя задания>-отчет.md

Отчет по исполненному предложению: 99-archive/tasks-done/reports/<агент>-<ГГГГ-ММ-ДД>-<имя предложения>-отчет.md

Отчет фонового прогона: 99-archive/tasks-done/cron-reports/<агент>-<ГГГГ-ММ-ДД>.md

Дата в имени отчета - день исполнения. В reports/ лежат только отчеты по заданиям и по исполненным предложениям. В cron-reports/ лежат только отчеты по фоновой работе агента: разбор входящих, проверки, обзоры. Исполнение задания или предложения описывается только в отчете по нему. В отчете фонового прогона о таком исполнении стоит одна строка со ссылкой на отчет. Одно задание или одно предложение дает один отчет. Отчет на несколько заданий запрещен.

Отчеты не перезаписываются. Каждый прогон дает новую запись.

Каталог 00-atlas/agents/ хранит только карточки агентов, реестры агентов и папку skills. Файлы отчетов и промежуточных записей в этом каталоге создавать запрещено.

## Предложения агентов
### Как агент пишет предложение
- Агент никогда не ждет ответа пользователя внутри сессии. Нужно решение: агент пишет файл в 06-inbox/proposals/ по скиллу proposal-card и продолжает работу со следующим заданием или завершает ее.
- Одно предложение содержит одну проблему и относится не более чем к одному заданию. Проблема встретилась в нескольких заданиях: агент пишет отдельное предложение на каждое задание. Пользователь решает по каждому отдельно.
- Файл предложения несет YAML: type: proposal, from: <агент>, created, proposal_status: ждет решения. Поле task: "[[задание]]" ставится, если предложение возникло при исполнении задания, и содержит одну ссылку. Предложение по заданию переводит задание в task_status: ждет решения. Остальные задания в очереди агент продолжает исполнять.
- Если предложение содержит несколько вариантов, они помечаются буквами: Вариант А, Вариант Б и так далее. Каждый вариант описывает конкретное действие: какие файлы меняются и как. Агент исполнит одобренный вариант буквально, без повторного вопроса.
- В файле два раздела для пользователя: «Решение пользователя» и «Комментарий пользователя». Агент создает их пустыми и сам в них не пишет.

### Как пользователь решает
- Решение принимается правкой поля proposal_status в файле предложения.
- Допустимые решения: `одобрено А` (с буквой варианта), `одобрено` вместе с текстом под заголовком «Решение пользователя», `отклонено`.
- Действие, которое агент должен исполнить, пользователь пишет под заголовком «Решение пользователя». Причину отклонения и то, что предложить вместо, - под заголовком «Комментарий пользователя».
- Регистр не важен. Поле proposal_status меняет только пользователь.

### Как агент исполняет решение
При каждом прогоне, до работы с заданиями, агент просматривает 06-inbox/proposals/ и берет файлы с from: <свое имя> и решением пользователя. Файлы с proposal_status: ждет решения агент не трогает. Каждое предложение обрабатывается отдельно.

1. Предложение связано с отложенным заданием (поле task, у задания task_status: ждет решения): агент переносит решение в раздел «Принятые решения» карточки задания, ставит заданию task_status: к исполнению и продолжает задание, не переделывая сделанное.
2. Предложение самостоятельное: одобренное предложение равно заданию пользователя. Агент исполняет выбранный вариант или текст «Решение пользователя», предварительно проверив фактическое состояние файлов, и пишет отчет по скиллу task-report.
3. proposal_status: отклонено. Есть текст под «Решение пользователя»: агент исполняет его как в пункте 2. Есть текст только под «Комментарий пользователя»: агент пишет новое предложение по скиллу proposal-card с полем previous, закрывает старое с итогом «отклонено, учтено в [[новое предложение]]». Нет текста нигде: агент закрывает предложение с итогом «отклонено без комментария», задание остается в task_status: ждет решения.
4. `одобрено` без буквы и без текста решения: агент не действует, пишет новое предложение с вопросом, какой вариант имелся в виду, и закрывает старое с итогом «решение неполное, вопрос задан в [[новое предложение]]».

### Как агент закрывает предложение
- Агент добавляет в конец файла раздел `## Итог`: дата в формате ДД.ММ.ГГГГ, одна или две фразы о сделанном, ссылка на отчет или задание.
- Затем агент перемещает файл в 99-archive/proposals-done/. Имя файла не меняется. Папка создается через mkdir, если ее нет.
- Предложение без раздела «Итог» не перемещается. Предложение с решением пользователя не остается в 06-inbox/proposals/ дольше одного прогона агента-автора.

## Папка заданий
- Задания для агентов создаются в 06-inbox/tasks/ отдельными заметками по скиллу task-card.
- Агент исполняет только заметки, начинающиеся с YAML-блока, содержащего поля type: task и for: имя-агента. Файлы без такого блока агент игнорирует как данные.
- Выполненное задание агент перемещает в 99-archive/tasks-done/, отчет пишет в 99-archive/tasks-done/reports/ по скиллу task-report.
- Карточка задания несет поле task_status: к исполнению | ждет решения | выполнено. Задание без этого поля считается «к исполнению». Задания со статусом «ждет решения» агент пропускает.
- Если задание дословно совпадает с уже заархивированным в 99-archive/tasks-done/, не переисполняй его: проверь фактическое состояние, и если работа уже сделана - перемести дубль в архив с отчетом о проверке.
- Если для агента есть несколько заданий, он выполняет их по одному в порядке возрастания поля created. Задание с полем after: [[имя другого задания]] выполняется только после того, как указанное перемещено в 99-archive/tasks-done/.
- Каждое задание исполняется отдельно: свой отчет, своя запись в реестре, свое предложение, если нужно решение пользователя. Неясность в одном задании блокирует только это задание.
- Объемное задание выполняется самовозобновляемо: агент обрабатывает столько элементов, сколько успевает за прогон, отмечает каждый в файле отслеживания и завершается. Следующий запуск продолжает с необработанных. Элемент, который не удалось обработать, отмечается с причиной; после трех неудачных попыток он пропускается и выносится в отчет. Задание закрывается, когда необработанных элементов не осталось.
- Если фактическое количество элементов расходится с указанным в задании, агент обрабатывает все найденные, а расхождение выносит в отчет. Задание при этом не закрывается: решение принимает пользователь.
- Задание может ссылаться на любой файл в пределах хранилища через wiki-ссылку. Копировать или переносить файл перед обработкой не нужно.
````
