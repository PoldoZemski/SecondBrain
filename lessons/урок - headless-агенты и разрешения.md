# Урок: headless-агенты и система разрешений

## Симптом-обманка
Агент "отработал" (процесс завершился штатно), но файлы не изменены; в его отчете: "инструмент требует разрешения, которое не выдано", "mkdir жестко блокируется". Похоже на баг или песочницу, а на деле это штатная система разрешений Claude Code, ждущая интерактивного подтверждения, которого в headless некому дать.

## Механика
- Даже разрешенные в --allowedTools операции записи по умолчанию требуют подтверждения; headless-запускам обязателен --permission-mode acceptEdits
- Bash не входит в базовые инструменты: mkdir/mv не работают, пока не выданы явно точечно: Bash(mv:*),Bash(mkdir:*)
- Кэш одобрения API-ключа (~/.claude.json): исправил ключ в .env, сотри файл и пройди онбординг заново, иначе молчаливое зависание

## Дизайн границ (проверен практикой)
- rm НЕ выдается никогда: "удаление" = mv в архив; ошибка агента обратима по определению
- Права возвышаются по мере доверия: разведка на Read/Glob, затем приемка отчета, затем рабочий набор с Write/mv
- Первое задание нового агента - опись без изменений; качество отчета = портрет сотрудника до выдачи прав

### Что инструменты делают на самом деле (проверено)
- Инструмент `Edit` СОЗДАЕТ новые файлы, а не только правит существующие. Проверка: агент-секретарь получил список без `Write` и создал две заметки (отчет секретаря и журнал в 99-archive/todo-log/).
- Вывод: отсутствие `Write` в списке не запрещает агенту создавать файлы. Не рассчитывайте на это как на ограничение.
- Единственная проверенная защита от необратимых действий: отсутствие `rm` в списке `Bash(...)`. Агент перемещает и создает файлы, но не удаляет их.
- Правило: проверяйте фактическое поведение инструмента опытом, не описанием.

## Правило
Формулировка агента о собственных ограничениях - ценная диагностика, но его ГИПОТЕЗА о причине может врать (валил на "кириллицу в путях" то, что было отсутствием инструмента). Сверяй с документацией механизма, а не с домыслом модели.

## Разные права для разных агентов
У Claude Code есть флаг --settings <путь>, позволяющий подать свой файл настроек на конкретный запуск. Это дает возможность развести права по агентам при одном системном пользователе: общий файл с широким deny для всех, отдельный для агента, которому нужно больше (например, методисту для правки скиллов).

*НЕ ПРОВЕРЕНО:* заменяет ли --settings базовый ~/.claude/settings.json или дополняет его. Правила deny объединяются между уровнями и не ослабляются менее авторитетным уровнем: если это работает и здесь, запрет из базового файла останется в силе, и схема не сработает. Проверять тестом, а не предположением.
