# Урок: Docker обходит UFW

## Ловушка

Файрвол UFW включен, политика deny incoming действует, статус UFW показывает, что порт закрыт. При этом порт, который контейнер опубликовал через `ports:`, доступен из интернета. Ни одна проверка статуса UFW об этом не сообщает.

## Причина

Docker сам создает правила в iptables для опубликованных портов. Трафик к контейнеру перенаправляется в таблице nat еще до цепочек INPUT и OUTPUT, которыми пользуется UFW. Пакеты маршрутизируются до применения правил UFW, и настройки UFW игнорируются. Сам Docker в документации называет эти два инструмента несовместимыми. Источник: https://docs.docker.com/engine/network/packet-filtering-firewalls/ (раздел Docker and ufw, страница проверена 19.10.2026).

На этом сервере инцидента с опубликованным портом не было. Урок основан на документации Docker и на правиле безопасности проекта: проверять фактическую доступность, а не статус UFW.

## Правило

1. Публикуйте через `ports:` только Traefik (80 и 443). Остальные сервисы работают за Traefik без `ports:`.
2. Порт, нужный только на самом сервере, привязывайте к localhost: `"127.0.0.1:5432:5432"`.
3. Порт, нужный контейнерам из docker-сети, открывайте правилом UFW для подсети Docker, а не для всех.
4. После запуска любого сервиса смотрите `sudo ss -tlnp`: адреса 0.0.0.0 и [::] допустимы только у осознанно открытых портов.
5. Проверяйте порт снаружи с устройства, не подключенного к вашему серверу и его VPN. Через собственный VPN запрос идет изнутри доверенной сети и показывает порт открытым при закрытом файрволе. Разбор: [урок - сеть между хостом и контейнерами](%D1%83%D1%80%D0%BE%D0%BA%20-%20%D1%81%D0%B5%D1%82%D1%8C%20%D0%BC%D0%B5%D0%B6%D0%B4%D1%83%20%D1%85%D0%BE%D1%81%D1%82%D0%BE%D0%BC%20%D0%B8%20%D0%BA%D0%BE%D0%BD%D1%82%D0%B5%D0%B9%D0%BD%D0%B5%D1%80%D0%B0%D0%BC%D0%B8.md).

## Признаки, что урок не усвоен

- Проверка доступности порта ограничивается командой `ufw status`.
- В compose-файле сервиса, который работает за Traefik, есть блок `ports:`.
- Порт проверен только с устройства, подключенного к серверу через VPN.
