# Урок: правка карточек через коннектор

Опыт: около 40 правок скиллов, CLAUDE.md, карточек агентов и руководств через коннектор obsidian-vault-bridge (инструменты vault_get_document_map, vault_read, vault_patch, vault_write, vault_append).

## Что обнаружилось

1. Правка поля metadata через vault_patch (targetType frontmatter) переформатирует шапку. Длинное description в agent-run разбилось на три строки. YAML остается валидным, но стандарт хранит description в одну строку. В task-report и yaml-frontmatter после той же правки формат шапки не проверялся.
2. Операция prepend к разделу с таблицей ставит текст перед шапкой таблицы: новая строка оказывается вне таблицы. Таблицу правят заменой раздела целиком.
3. Заголовок в target передается массивом от верхнего уровня: полный путь, строка вместо массива не принимается.
4. Уровни заголовков в content считаются от цели. Новый раздел рядом с существующим вставляет append со scope markerAndContent и заголовком первого уровня: раздел встал соседним, карта документа это подтвердила.
5. Заголовки внутри блока кода карта документа не считает заголовками. Образец карточки с заголовками внутри блока markdown структуру файла не ломает.
6. Замена раздела целиком требует дословной копии всего остального текста раздела. Пропущенная строка теряется без предупреждения.
7. Параметры вызова не черновик. Вызов, отправленный по ошибке, выполняется: в раздел руководства записалось слово-заглушка, исправлено заменой раздела на исходный текст.
8. Вызовы с текстом до 6 КБ за раз в этой серии проходили без сбоев. Пачка из 22 параллельных чтений повесила коннектор, порции по 3-7 чтений проходили. Запись большими объемами и пачками файлов тоже зависала (см. главу [11-obsidian mcp для claude desktop](../guide/11-obsidian%20mcp%20%D0%B4%D0%BB%D1%8F%20claude%20desktop.md), раздел «Ограничения»).
9. После разрыва связи с хранилищем инструменты коннектора перестали находиться. Загрузка по имени через ToolSearch вернула их, когда мост снова заработал.
10. В очень длинном чате инструменты коннектора могут перестать загружаться, даже если мост работает (причина не установлена). Перезапуск Claude Desktop в уже открытый чат инструменты не возвращает, помогает новый чат в том же проекте.
11. Инструмент vault_get_upload_url из облачной среды чата не работает: адрес указывает на локальный компьютер, вызов завис без результата.
12. Поиск search_simple с несколькими словами разбирает запрос по отдельным символам и возвращает огромный вывод. Для точного поиска используйте search_query с регулярным выражением по полю content или path.
13. Результат работы search_query возвращает только пути, если условие ограничить параметром if и вернуть var path. Это быстрый способ проверить все файлы на соответствие правилу (например, найти все index.md, которые не совпадают с эталоном).
14. Операция append с targetType heading сдвигает уровни заголовков в добавляемом тексте на уровень целевого заголовка: при цели первого уровня «## Раздел» превращается в «### Раздел». Чтобы получить раздел второго уровня под целью первого уровня, пиши «# Раздел». Ошибка видна только в карте документа: разделы оказываются вложенными в соседние. Исправление: удалить вложенный раздел операцией delete со scope markerAndContent и добавить его заново с правильным числом решеток.
15. Файл, созданный в 06-inbox/, архивариус забирает сразу: временную заметку для проверки операций нельзя оставлять во входящих, она окажется в 99-archive/inbox-processed/. Для проверок используй свою рабочую папку вне inbox.

## Правило

- Перед правкой раздела получить карту документа и прочитать раздел точечно.
- После правки прочитать результат: раздел, таблицу или поле шапки.
- Таблицы заменять целиком, строки в начало раздела не вставлять.
- Шапку после правки метаданных проверять на перенос строк.
- Не отправлять вызов записи «на пробу».
- При замене раздела копировать текст дословно и сверять после записи.

## Как проверить

Каждый пункт 1-9 наблюдался на живом хранилище.

## Признаки, что урок не усвоен

- Правка без чтения результата.
- Строка добавлена в таблицу через prepend.
- После правки шапки description разбит на строки и никто этого не заметил.
- Раздел заменен целиком по памяти, а не по прочитанному тексту.
