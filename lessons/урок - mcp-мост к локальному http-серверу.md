# Урок: mcp-мост к локальному http-серверу

Контекст: нужно было подключить Claude Desktop к уже работающему локальному MCP-серверу (плагин Obsidian, Streamable HTTP на 127.0.0.1). Ожидание: указать адрес в настройках. Реальность: два отдельных препятствия, ни одно не очевидно из формулировки задачи.

## Ловушка первая: формат расширений понимает только локальные процессы

MCPB (формат расширений Claude Desktop) описывает не "куда подключаться", а "какой процесс запустить и как с ним говорить по stdio". Спецификация (modelcontextprotocol/mcpb, файл MANIFEST.md) перечисляет ровно 4 типа сервера: node, python, binary, uv. Все они про то, чем и как Claude Desktop запускает локальный процесс. Типа "http"/"url"/"remote" не существует в принципе: это не пробел в документации, а осознанная граница формата.

Решение: не искать способ прописать URL в манифесте, а завернуть HTTP-сервер в маленький локальный stdio-процесс. Готовый инструмент для этого - пакет mcp-remote (npm, geelen/mcp-remote): CLI, который слушает stdio с одной стороны и говорит по HTTP с другой, включая заголовки авторизации (`--header "Authorization:Bearer <токен>"`). Расширение MCPB типа node просто запускает этот пакет как entry_point, вендоря его вместе с node_modules внутрь пакета расширения.

## Ловушка вторая: самоподписанный сертификат ломает fetch по умолчанию

Локальный HTTP-сервер плагина слушает на https с самоподписанным сертификатом (типично для локальных инструментов, которые никто не собирается открывать наружу). Node (через undici) по умолчанию проверяет цепочку доверия и такой сертификат отклоняет: соединение падает с ошибкой на уровне TLS, а не MCP-протокола, что сначала выглядит как проблема авторизации или доступности сервера.

Ложный путь: гасить проверку сертификата (NODE_TLS_REJECT_UNAUTHORIZED=0) ради одного локального соединения. Работает, но по умолчанию отключает проверку для всего процесса целиком, лишний риск ради надуманной проблемы.

Верный путь: если у сервиса есть штатный небезопасный HTTP-режим специально для localhost (как у этого плагина: тумблер "Enable HTTP server", порт слушает только 127.0.0.1), использовать его вместо борьбы с сертификатом на https-порту. Трафик не покидает машину в обоих случаях, а конфигурации меньше.

## Правило

Прежде чем городить обход (TLS, самодельные заголовки, самодельный протокол-мост), проверить, нет ли у используемого инструмента штатного локального режима именно под эту ситуацию, и не упирается ли задача в документированную границу формата (как здесь, в спецификацию MCPB). Такую границу обходят не борьбой с симптомом, а подходящей архитектурой (прокси-процесс), а не патчем поверх нее.
