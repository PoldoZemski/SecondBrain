# Урок: CouchDB - это не файлы

## Ловушка планирования

Схемы вида "Obsidian sync через CouchDB + агенты работают с vault на сервере" молча монтируют в контейнеры агентов папку ./vault, которую НИЧТО не наполняет. CouchDB хранит заметки как документы-чанки в своей базе; на файловой системе сервера vault не появляется вовсе. Логический разрыв виден только при попытке запуска: папка пуста.

## Следствия

1. Между CouchDB и файлами обязателен материализатор: livesync-bridge (отдельный сервис, свой слой граблей).
2. Выбор технологии синхронизации - это выбор всей цепочки: Syncthing дает файлы сразу (но нет iOS); CouchDB дает iOS (но требует bridge). Требование "iPhone" решает спор.
3. Читая чужую схему, ищи не то, что в ней есть, а то, чего в ней нет: кто наполняет каждый смонтированный том?
4. Структура каталогов тоже не "файл" для БД: пустые папки не доезжают до устройств, см. ## Правило

Для каждого volume в схеме ответь: какой процесс пишет сюда данные и откуда они берутся физически. Нет ответа: дыра в архитектуре.
