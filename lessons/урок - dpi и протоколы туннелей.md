# Урок: DPI, гео-блоки и туннели (сетевая сага)

## Хроника поражений и победа
1. api.anthropic.com напрямую из РФ: 403 (гео-блок по IP).
2. Cloudflare WARP (бесплатный) подключает БЛИЖАЙШИЙ узел, выход в Москве, тот же 403. Инструмент исправен и бесполезен.
3. Свой vless+reality сервер: с домашнего провайдера работает, с VPS в дата-центре рвется. В логах клиента: "REALITY: received real certificate (potential MITM)". Это значит, что DPI сети хостинга активно перехватывает рукопожатие и подсовывает настоящий сертификат сайта-маскировки. Протокол опознан и подавлен.
4. Победа: НОВЫЙ сервер (свежий IP, NL) с тем же Reality, DPI-сигнатуры не сработали. Альтернатива на случай рецидива: Shadowsocks-2022 (нет TLS-рукопожатия, нечего перехватывать).

## Диагностический словарик
| Наблюдение | Значение |
|---|---|
| 403 от API | гео-блок; канал жив |
| 404 от корня API | ПОБЕДА: гео пройден, API отвечает |
| 000 / таймаут | туннель мертв на маршруте |
| работает дома, не работает с VPS | DPI провайдера VPS давит протокол |
| received real certificate | активный перехват Reality |

## Правила
1. У каждого провайдера свой DPI: "протокол работает" - свойство МАРШРУТА, не протокола.
2. Диагностируй лесенкой: ifconfig.me через прокси (туннель жив?), затем ipinfo (страна выхода?), затем целевой API (гео?). Каждая ступень отсекает свой класс причин.
3. Автономным агентам нужен скучный стабильный канал: прокси-переменные в .env воркера, NO_PROXY для локального, и мониторинг журнала клиента при загадочных сбоях.
4. curl-диагностику веди с сервера напрямую (docker exec / без прокси-переменных сессии): окружение искажает картину.

## Один Xray, разные потребители

Прокси нужен не только процессам на хосте, но и контейнерам: Telegram API блокируется так же, как api.anthropic.com.

Схема с двумя входами Xray: 10808 (SOCKS) слушает 127.0.0.1, 10809 (HTTP) слушает все интерфейсы и закрыт файрволом от интернета: разрешена только подсеть docker-сети. Claude Code работает через HTTP-вход 10809 по адресу 127.0.0.1, контейнеры через тот же порт по адресу шлюза docker-сети. Проверено выводом `ss -tlnp` и `ufw status numbered`.
