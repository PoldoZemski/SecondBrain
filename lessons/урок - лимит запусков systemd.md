# Урок: лимит запусков systemd останавливает path-юниты агентов

Опыт 22-27.10.2026. Библиотекарь, методист и секретарь пять дней не реагировали на новые задания. Работали только по почасовому cron.

## Симптом

`systemctl list-units` показывает path-юниты агентов в состоянии failed. `systemctl status` показывает `Result: unit-start-limit-hit`. Все три юнита упали в одну секунду: 22.10.2026, 09:04:10 UTC. Архивариус в тот момент выжил.

## Причина

1. У каждого сервиса systemd по умолчанию есть лимит частоты запусков: 5 запусков за 10 секунд.
2. Path-юнит запускает сервис на каждое событие в папке. Мост LiveSync и массовые перемещения файлов дают пачку событий за секунды.
3. Скрипт агента без работы выходит за доли секунды. Systemd успевает запустить его больше пяти раз за 10 секунд, срабатывает лимит, и path-юнит встает до ручного сброса.
4. Вероятная причина, почему выжил архивариус (не проверено): у него в тот момент была работа, Claude работал минутами, а oneshot-сервис в состоянии «выполняется» новые запуски не принимает.

## Решение

Drop-in без лимита запусков для сервиса каждого агента. Исходный unit-файл не меняется:

```bash
sudo mkdir -p /etc/systemd/system/<имя>.service.d
printf '[Unit]\nStartLimitIntervalSec=0\n' | sudo tee /etc/systemd/system/<имя>.service.d/no-start-limit.conf > /dev/null
sudo systemctl daemon-reload
sudo systemctl reset-failed <имя>-watch.path <имя>.service
sudo systemctl restart <имя>-watch.path
```

Снятие лимита безопасно: от двойного запуска защищает flock в скрипте, холостой запуск не вызывает Claude и ничего не стоит.

Проверка: `systemctl show <имя>.service -p StartLimitIntervalUSec` дает `StartLimitIntervalUSec=0`, path-юнит в состоянии active waiting.

Применено 27.10.2026 к архивариусу, библиотекарю, методисту, секретарю и бизнес-аналитику.

## Правило

Каждый сервис агента, который запускает path-юнит, получает drop-in no-start-limit.conf при установке. Почасовой cron остается страховкой: он и держал агентов эти пять дней.

## Признаки, что урок не усвоен

- Агент реагирует на задание только на своей минуте cron, а не за секунды.
- В `systemctl list-units --all --type=path` есть юнит со значком ● и словом failed.
