# Урок: десктопные расширения claude доступны из cowork

## Симптом-обманка

Официальная документация по коннекторам различает два типа: "Web"-коннекторы (работают на серверах разработчика, доступны из Cowork/веба/мобильного по построению) и "Desktop"-расширения (MCPB/DXT, локальный процесс на компьютере пользователя). Прямое прочтение наводит на вывод: раз Cowork - облачная сессия без прямого доступа к устройству пользователя, то локальные Desktop-расширения ей не могут быть доступны в принципе.

## Проверка на практике

У пользователя уже стояло стороннее Desktop-расширение, установленное через MCPB/DXT. Его инструменты оказались видны в этой самой Cowork-сессии с префиксом `mcp__remote-devices__<имя-расширения>__*`. То есть локальное расширение действительно проксируется в облачную сессию через тот же мост к устройству пользователя, что дает доступ к файлам и управлению курсором на компьютере. После установки второго такого расширения (моста к Obsidian, тоже MCPB) картина повторилась: инструменты появились в сессии без дополнительной настройки, сразу после установки в Claude Desktop.

## Правило

Общее описание коннекторов ("desktop-расширения не в Cowork") не подтвердилось для собственных локальных MCPB-расширений, устанавливаемых через Settings, Extensions на устройстве, к которому подключена сессия: они проксируются в Cowork автоматически. Не отказываться от идеи подключить локальный сервис через MCPB-расширение только на основании общего текста документации: проверять эмпирически, install-then-check, благо стоимость проверки - один клик установки.

## Открытый вопрос

Точный механизм проксирования (что именно решает, какие расширения видны в Cowork, а какие нет) не выяснен: правило проверено только для двух конкретных случаев. Не считать доказанным для всех типов расширений без собственной проверки.
