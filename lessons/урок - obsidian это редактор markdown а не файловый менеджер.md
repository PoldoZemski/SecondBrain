# Урок: Obsidian - редактор markdown, а не файловый менеджер

## Симптом

Файл .py положен в папку хранилища через проводник операционной системы. Он физически лежит на диске, но в дереве Obsidian его нет. После включения показа всех расширений файл виден, но не открывается для правки.

## Причина

1. Obsidian по умолчанию показывает только .md, изображения, PDF, аудио, видео, .canvas и .base. Остальные типы скрыты.
2. Тумблер Settings, Files and links, Detect all file extensions делает такие файлы видимыми, но редактор для них не открывается: Obsidian умеет править только markdown.

## Следствие для архитектуры агентов

Скиллы из одного файла SKILL.md правятся с телефона и синхронизируются как обычные заметки. Скиллы со скриптами внутри таким образом не правятся: скрипт меняют сторонним редактором (nano или vim на сервере, VS Code). Изменение скрипта требует доступа к серверу, то есть выпадает из схемы «управление агентами - это заметки в хранилище».

## Правило

Логику, которую предполагается часто менять, держите в SKILL.md текстом. В скрипт выносите только то, что должно быть детерминированным и меняется редко: проверки по фиксированному списку правил.

Общий признак класса: «вижу в интерфейсе» не равно «могу изменить», как «поправил compose» не равно «контейнер пересоздан».

## Признаки, что урок не усвоен

- Часто меняемая логика агента зашита в скрипт внутри скилла.
- Файл, положенный через проводник, «пропал» из Obsidian, и его ищут в синхронизации.
