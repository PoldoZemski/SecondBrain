# Урок: команды, отработавшие не так, как выглядели

## Общий признак
Команда не выдала ошибки. Результат отличается от ожидаемого. Обнаруживается позже и не там, где была допущена.

## Случаи из проекта

**ln -s в существующий каталог.** Связка `mkdir -p ~/.claude/skills` + `ln -s <цель> ~/.claude/skills` дает не симлинк вместо каталога, а симлинк внутри него. ln видит существующий каталог и кладет ссылку туда. Итог: skills/skills - вложенная ссылка, новые скиллы не подхватываются. Проверка: ls -la родительского каталога, ищем строку с «l» в начале и стрелкой.

**Оборванная кавычка.** `--allowedTools "Bash(rm:*)` без закрывающей кавычки на той же строке: bash показывает приглашение продолжения > и подставляет перевод строки внутрь аргумента. Значение не совпадает ни с одним правилом. Тест защиты проходит успешно по неверной причине.

**Слэш в конце имени файла.** `~/bin/claude/ -p "..."` дает «Not a directory». Слэш заставляет оболочку искать каталог. Одна из немногих ошибок этого класса, дающая внятное сообщение.

**chmod +x** - см. [урок - права и владельцы в multi-user](%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%BF%D1%80%D0%B0%D0%B2%D0%B0%20%D0%B8%20%D0%B2%D0%BB%D0%B0%D0%B4%D0%B5%D0%BB%D1%8C%D1%86%D1%8B%20%D0%B2%20multi-user.md).

*Правило:* результат команды проверяется отдельной командой, а не отсутствием ошибки. После ln -s - ls -la. После chmod - ls -l. После правки конфига - тест, который использует измененное.

Ответ агента результатом не является: «файл не удален», «правка внесена» - это его модель происходящего. За вечер отладки расхождение с фактом всплывало дважды.

**exec замещает процесс** - после него ничего не выполнится. Строка `exec claude -p ...` заменяет процесс скрипта процессом claude. Все, написанное ниже, не выполняется никогда. Ошибки нет, предупреждения нет - код просто мертв.

*Проявление:* коммит после работы агента, обновление метки времени, уборка временных файлов молча не работают, если стоят после exec.

*Правило:* exec только если после вызова действительно ничего не нужно. Нужно хоть что-то - обычный вызов без exec.

## Опечатки в путях, которые не дают ошибки

Из одной сессии правки трех run-скриптов:
* `vault-commit/sh` вместо `vault-commit.sh` - слэш вместо точки, четыре раза в трех файлах
* `06-inbox.tasks.` вместо `06-inbox/tasks/` - точки вместо слэшей; grep с подавленным stderr молча возвращает пустоту, переменная всегда пуста, агент не запускается никогда
* `run-secratary.sh` вместо `run-secretary.sh` - расхождение имени файла с тем, что прописано в cron и systemd
* обрыв строки: `2` вместо `2>&1` - stderr уходит в никуда, ошибки агента невидимы
* незакрытая скобка в --allowedTools: правило невалидно, разрешение не работает, но выглядит настроенным

*Общее:* bash не проверяет существование путей и не жалуется на несуществующие. Ошибка проявляется как «ничего не произошло». Проверка синтаксиса без запуска: bash -n <скрипт> ловит незакрытые кавычки и скобки. НЕ ловит опечатки в путях - они синтаксически корректны. Эти проверяются только тестом.

## Проверка результата командой, а не чтением отчета

Правило «результат проверяется командой ОС, а не словами агента» получило продолжение: команду проверки стоит писать заранее и вкладывать в само задание.

Пример из миграции контактов:

```bash
grep -l "next_touchpoint_due: 202" <папка>/*/*.md
grep -rl "2026-08-06 |" <папка>
```

Обе должны вернуть пусто. Пока их не было, приемка шла по тексту отчета и дважды пропустила необработанную партию.

Побочный эффект: агент, получив команды в задании, выполняет их сам и приводит вывод. «Сделано» становится проверяемым.
