# Урок: стоимость работы агентов

## Инцидент
За один день отладки агенты израсходовали $20. Модель по умолчанию - Opus. Разбор показал: часть суммы неизбежна (разовая миграция 100+ файлов), часть - прямая утечка на ошибках конфигурации.

## Три источника расхода

**1. Модель.** Главный рычаг. Разница Opus/Haiku примерно двадцатикратная, Opus/Sonnet - пятикратная. Модель по умолчанию - самая мощная, то есть самая дорогая.

Флаг --model принимает алиас последней версии (haiku, sonnet, opus) или полное имя. Задавать явно в каждом run-скрипте.

Соответствие агент и модель по характеру работы:
* механическая работа по фиксированным правилам (проверка ссылок, перенос строк по [x], проверка имен) - haiku
* работа с суждением (куда положить заметку, что из текста существенно) - sonnet
* opus только там, где доказана недостаточность sonnet

**2. Холостые пробуждения.** Path-юнит срабатывает на ЛЮБОЕ изменение в отслеживаемой папке. Архивариус перемещает свое выполненное задание из 06-inbox/tasks/, и это изменение будит библиотекаря. Тот запускается, грузит промпт и CLAUDE.md, выясняет, что заданий для него нет, завершается. Оплаченный вызов на пустом месте.

Лечится условием раннего выхода ДО вызова claude:

```bash
TASKS=$(grep -rl "for: <агент>" 06-inbox/tasks/ 2>/dev/null)
if [ -z "$TASKS" ]; then exit 0; fi
```

Проверка стоит доли секунды, вызов - центы. При десятке заданий в день разница накапливается.

**3. Постоянная стоимость запуска.** Каждый вызов грузит CLAUDE.md, промпт агента и шапки всех скиллов: платится всегда, даже если работы на одну строку. Отсюда: CLAUDE.md держать компактным, детали выносить в скиллы (подгружаются только при релевантности), частоту запусков по расписанию не завышать.

## Детерминированную работу - в скрипты
Проверка имен на запрещенные символы, поиск битых ссылок, поиск невидимых символов - это grep и find, не работа модели. Агент, читающий сотню файлов ради регулярки, платит за каждый.

Правильно: скрипт собирает список проблем, агент получает готовый короткий список и решает, что с ним делать. Разница на порядок.

## Дробить объем - не тот рычаг
Изначально казалось, что задание на 100 файлов надо дробить на партии: дешевле и видно результат до конца работы. Опыт показал обратное: дробление переносит стоимость с токенов на ручной труд человека. Пять партий = пять приемок.

Правильный способ ограничить расход - самовозобновляемое задание (агент делает сколько успевает и продолжает следующим запуском) плюс дешевая модель. Объем при этом не ограничивается искусственно. Подробно - [урок - задания агентам](%D1%83%D1%80%D0%BE%D0%BA%20-%20%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D1%8F%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%B0%D0%BC.md).

Что действительно снижает расход: выбор модели, отсечение холостых пробуждений, вынос детерминированных проверок в скрипты.

## Обязательное
Лимит трат в Console - до запуска любых агентов по расписанию. Ошибка в цикле (зацикленное задание, бесконечный перезапуск) съедает баланс за ночь без всякой пользы.

Автопополнение на этапе отладки выключить: лучше упереться в ноль и разобраться, чем обнаружить растущий счет.

## Признаки, что урок не усвоен
* В run-скрипте нет флага --model.
* Скрипт вызывает claude безусловно, без проверки наличия работы.
* Проверка по фиксированным правилам поручена модели, а не скрипту.
* Лимит трат не установлен.
