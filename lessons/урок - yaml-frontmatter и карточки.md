# Урок: YAML-frontmatter и типичные ошибки в карточках

Опыт работы агентов с карточками заданий и контактов. Агенты стабильно допускали одни и те же ошибки YAML, несмотря на наличие правил в CLAUDE.md.

## Симптом

Агенты создавали карточки с YAML-ошибками трех типов:

Первый - неверный формат тегов. Встречались все три запрещенных варианта: строка через запятую (`tags: "#тег1, #тег2"`), инлайн-список (`tags: ["#тег1"]`), тег без кавычек (`- #тег1`). Последний - синтаксическая ошибка YAML: `#` без кавычек означает комментарий, тег молча игнорируется парсером.

Второй - wiki-ссылки в YAML без кавычек. Символы `[[` и `]]` специальные в YAML. Запись `task: [[имя задания]]` ломает парсер; нужно `task: "[[имя задания]]"`.

Третий - инлайн-списки вместо блочных. Поля типа `sphere` или `after` записывались как `["[[ссылка1]]", "[[ссылка2]]"]` вместо блочного списка с дефисами.

## Причина

Правила были разбросаны по трем местам: CLAUDE.md (общие), скилл task-report (теги в отчетах), скилл contact-card (теги и даты в контактах). Между местами были расхождения - например, скилл naming-check использовал инлайн-формат `allowed-tools: [Read, Glob, Grep]` вопреки общему правилу. Агент, читающий несколько источников с противоречиями, выбирает произвольно.

## Решение

Создан скилл `yaml-frontmatter` как единый источник правды по YAML. Все остальные скиллы ссылаются на него вместо дублирования правил. Скилл описывает:
- общие правила (имена полей, даты, пустые поля, спецсимволы)
- единый блочный формат для всех списков без исключений
- формат тегов с примерами запрещенных вариантов
- формат wiki-ссылок в YAML-полях (одиночные и списки)
- обязательные поля по типам карточек (task, proposal, report, заметка, скилл)

Шаблон скилла: [шаблон скилла yaml-frontmatter](../starter/%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%B0%20yaml-frontmatter.md).

## Правило

Любое новое поле с wiki-ссылкой или списком в YAML - проверять по скиллу yaml-frontmatter перед записью, а не по памяти.

## Чек-лист перед созданием карточки

- Теги оформлены блочным списком? Нет ли тега со знаком `#` без кавычек (он теряется как комментарий)?
- Wiki-ссылки в YAML взяты в двойные кавычки?
- Списки оформлены блочно (дефис + отступ), не инлайн?
- Дата в YAML в формате ГГГГ-ММ-ДД (ISO 8601)? Дата в тексте карточки, например в разделе «История», остается ДД.ММ.ГГГГ.
- Есть поля `type` и `направление`? Значение `type` взято из закрытого списка скилла yaml-frontmatter?
- Пустые поля оставлены пустыми, не заполнены «нет данных»?

## Как правило менялось со временем

Первая версия скилла требовала даты ДД.ММ.ГГГГ. Позже скилл перешел на ГГГГ-ММ-ДД: этот формат понимают Obsidian Properties, Bases и сортировка по дате. В старых карточках встречаются оба формата. Новые и обновляемые карточки получают ISO-дату.

Поля `type` и `направление` обязательны для всех заметок, кроме служебных index.md. Значение `type` берется из закрытого списка.

Требования к знаку `#` и кавычкам в тегах менялись: сначала кавычки и `#` внутри, потом `#` запрещен. Сейчас обязательности нет: записи `тег`, `"тег"` и `"#тег"` равнозначны. Недопустима только запись `#тег` без кавычек.

Для зеркал внешних ресурсов (файлы, которые перезаписывает скрипт обновления) стандарт хранилища не применяется к каждому файлу: ручные правки шапок пропадут. Стандарт применяется к корневой карточке ресурса.

## Признаки, что урок не усвоен

- Теги в YAML записаны строкой через запятую, инлайн-списком или как `#тег` без кавычек.
- `[[ссылка]]` в YAML-поле без кавычек.
- Поле `allowed-tools` или любой другой список в инлайн-формате `[...]`.
- Скилл правит правила YAML у себя, не ссылаясь на yaml-frontmatter.
