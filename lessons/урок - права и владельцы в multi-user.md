# Урок: права и владельцы в multi-user системе

## Контекст
Система с несколькими действующими лицами: админ (sudo), воркер агентов (без sudo), контейнеры (свои UID внутри). Файлы и каталоги общей зоны должны быть доступны всем законным участникам и никому сверх того. Каждое нарушение этой настройки проявлялось по-своему.

## Коллекция случаев
| Симптом | Причина | Лечение |
|---|---|---|
| git: dubious ownership | git от root в каталоге воркера | выполнять от владельца: sudo -u brain git ... |
| tail: Permission denied на лог | лог 600 у воркера, читает админ | логи в общий каталог с setgid 2775 |
| Jupyter: Permission denied при сохранении | том на хосте принадлежит root, контейнер живет от 1000 | chown -R 1000:100 на хостовую папку |
| deno install: Permission denied в /deno-dir | кэш в образе принадлежит чужому UID | внешний кэш-том и DENO_DIR |
| файлы агента с чужой группой | забыт setgid на каталоге | chmod 2775, новые файлы наследуют группу |
| bridge: PermissionDenied в логах на части файлов, устройства не получают правку с сервера | ручной sudo mkdir или mv в общей папке хранилища без -u: новый объект достается root, а не сервисному пользователю | sudo chown -R brain:secondbrain на затронутый каталог; --reset моста обычно не нужен, он сам досинхронизирует |

## Ключевые механики
1. Linux оперирует числами (UID, GID), имена - этикетки. Контейнер и хост видят одни числа: `user: "1500:1600"` в compose означает владельца brain:secondbrain на хосте. Совпадение чисел - совпадение прав. Побочный эффект: хостовый ls может показать другое имя с тем же числом, это не ошибка.
2. Фиксируйте UID и GID явно при создании (useradd -u, groupadd -g): автовыдача делает числа непереносимыми между машинами.
3. setgid на каталоге (chmod 2775): новые файлы наследуют группу каталога, а не первичную группу создателя. Обязателен для общих зон.
4. Секреты - противоположный полюс: права 600 и один владелец. Общая зона и зона секретов не пересекаются.
5. sudo без -u поднимает действие до root, а не до сервисного пользователя зоны. mkdir, mv, touch голым sudo в общей папке отдают новый объект root, и сервис с не-root UID получит Permission denied. Администрируйте общую зону от ее владельца: `sudo -u brain mkdir ...`, а не от root.

## Правило
Проектируй права ДО заселения: пользователи, группа, числа, setgid - на пустых каталогах это пять команд, на живой системе это археология с chown -R по следам ошибок.

## chmod без адресата раздает права всем
Форма `chmod +x файл` эквивалентна `a+x`: добавляет бит исполнения владельцу, группе И остальным. Umask маскирует только биты записи, исполнение не трогает. Результат: -rwxr-x--x вместо ожидаемого -rwxr-x---.

Для shell-скрипта вреда почти нет (без права чтения запустить нельзя), но расхождение с соседними файлами через полгода выглядит как чье-то осознанное решение.

Правило: права задавать числом (chmod 750), а не относительной формой. Число описывает результат, относительная форма - только прибавку к состоянию, которое в этот момент обычно уже не помнишь. Нужна относительная - с явным адресатом: u+x.

Копирование с сохранением прав и владельца: cp -p. Одна команда вместо связки cp + chown + chmod, и нечему разъехаться.
