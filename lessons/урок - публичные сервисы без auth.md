# Урок: публичный сервис без auth не живет ни дня

## Инцидент
Langflow опубликован через reverse proxy без аутентификации ("настрою позже"). Сервер скомпрометирован через его API (RCE), превращен в криптомайнер. Обнаружено по жалобе провайдера на загрузку CPU.

## Почему "мой домен никто не знает" - иллюзия
Сертификат Let's Encrypt публикуется в Certificate Transparency логах в момент выдачи; боты мониторят CT-поток и сканируют новые хосты В ТЕЧЕНИЕ ЧАСОВ. Публикация домена = приглашение сканерам, приватность имени не существует.

## Правила
1. Auth включается ДО первой публикации, не после.
2. Нативная auth сервиса лучше Basic Auth прокси (SPA с Basic Auth конфликтуют - проверено на Langflow).
3. Нет необходимости в домене (long-polling бот): нет traefik-labels вовсе, не создавай дверей.
4. Ежемесячная ревизия: docker ps + открытые порты + "все ли нужно?". Ненужное удалять (code-server удален именно так).
5. Следы инцидента (заблокированные IP в ufw) документировать в карточке сети: иначе через год правило станет загадкой.

## Открытый прокси - та же категория риска

Прокси, слушающий 0.0.0.0 без правила файрвола, находят сканерами за часы. Последствия те же, что с Langflow: через сервер начинают гонять чужой трафик, и отвечает за это владелец сервера.

Порядок действий обязателен: сначала правило файрвола, потом открытие порта. Не наоборот.

После открытия - обязательная проверка снаружи, с машины без VPN к этому серверу.
