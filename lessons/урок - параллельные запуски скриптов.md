# Урок: параллельные запуски одного скрипта

## Симптом
В журнале сервиса агента появляется ошибка git: `Unable to create '.../index.lock': File exists`. Агент при этом работает. Падает только коммит хранилища.

## Причина
Один скрипт коммита вызывают пять источников: крон каждый час и четыре агента до и после работы. Два вызова совпали по времени. Git не допускает параллельной записи в индекс. Второй процесс упал.

Событийный запуск усиливает проблему. Крон дает предсказуемое расписание. События приходят пачками и совпадают с плановыми прогонами.

## Решение
Очередь через flock. Две строки в начале скрипта, сразу после шебанга:

```bash
exec 200>/tmp/vault-commit.lock
flock -w 60 200 || exit 0
```

Второй вызов ждет до 60 секунд и выходит без ошибки. Файл блокировки git больше не появляется.

## Диагностика
- Проверка живого процесса git: `pgrep -a "^git"`. Команда `ps aux | grep git` дает ложные срабатывания: слово git встречается внутри длинного промпта агента в командной строке.
- Файл блокировки после падения обычно снимается сам. Проверьте наличие перед удалением: `sudo ls -la <репозиторий>/index.lock`.
- Каталоги пользователя-агента закрыты для администратора. Проверки выполняйте через sudo, права не меняйте.

## Правило
Скрипт, который вызывают несколько источников, защищайте блокировкой сразу при создании. Это дешевле, чем ловить редкие падения позже.
